# Nako 插件化画布

Nako 将画布、项目、媒体、生成、工作流、Agent、本地工作区和桌面功能按模块管理，通过声明式插件目录启动。运行和构建只使用本仓库的 `apps/`、`modules/`、`plugins/` .
## 启动

Windows x64，Node.js **24.20.0**：

```powershell
cd C:\Users\NAKO-06\Desktop\canvas\Nako
npm.cmd ci
npm.cmd --prefix apps/desktop ci
npm.cmd run desktop:dev
```

依赖已安装时只需最后一行。该命令检查并补齐本项目 `bin/` 下的 FFmpeg/ffprobe，构建画布与启动器后启动 Electron；源码版用户数据位于 `.desktop-dev/`。媒体组件首次安装需要联网，之后本地检查通过即跳过下载。无需官方账号登录。第三方模型调用仍需联网，模型密钥在设置中配置，本地 ComfyUI 另行安装。

媒体组件可单独安装与检查：

```powershell
npm.cmd run media:setup
npm.cmd run media:check
npm.cmd run smoke:media
```

安装固定版本 FFmpeg 9.0.1 的 Windows x64 essentials 构建，解压前校验 SHA-256，保留许可证与上游 README；不读取其他应用的组件或修改系统 PATH。离线安装可使用 `npm.cmd run media:setup -- --archive C:\path\ffmpeg-9.0.1-essentials_build.zip`，仍执行同一校验。视频/音频上传依赖 ffprobe，抽帧与剪辑依赖 ffmpeg；不应跳过内容检查来绕过安装问题。

## 分享画布工作流

打开画布左上角项目菜单，选择「导出画布工作流」。应用先保存当前编辑，再下载 `.nako` 文件，包含节点、连线、分组、提示词、模型参数、视口、当前项目媒体目录中的素材，以及 Agent 已保存的全部聊天会话和分支。保存失败或仍有未保存编辑时不会导出。

接收方从同一菜单选择「导入画布工作流」，选择 `.nako` 文件即可打开独立项目；当前画布先保存，重复导入不会覆盖已有项目，也不会恢复发送者的在途生成任务。模型来源、API Key 和本地运行环境需要接收方自行配置，工作流不会自动开始生成。

聊天历史保留消息、附件引用与工具操作状态；导入后新建独立会话，打开 Agent 面板会自动加载原活动会话。生成确认卡、预算授权、撤销回执和运行中任务不会作为可执行操作恢复，接收方继续生成需要重新确认。整库备份和项目复制也包含聊天历史；API Key、用户草稿和 Skill 文件不随聊天归档迁移。运行中的对话导出截至读取时已保存的消息。

导入入口也接受项目 JSON，但 JSON 仅含画布结构，不包含独立素材或聊天记录；跨设备分享请使用 `.nako`。外部网址和其他项目的素材引用不会自动下载打包；需要随包分享的素材应先导入当前项目。归档导入上限为 2 GiB，聊天归档上限为 32 MiB。含聊天记录的备份需要启用 Agent 插件后导入。

## 结构

| 目录 | 职责 |
| --- | --- |
| `apps/canvas` | 浏览器宿主启动，挂载插件提供的 `ui.root` |
| `apps/backend` | HTTP 安全边界、插件宿主、路由挂载、进程生命周期 |
| `apps/desktop` | Electron 窗口、IPC、平台环境；本地工作区由插件提供 |
| `modules/contracts`、`modules/kernel` | 公共协议、插件生命周期、服务、事件、权限与回滚 |
| 其余 `modules/*` | 各领域自己的 `ui/`、`server/`、`desktop/` 和公开 `api/` |
| `plugins` | Provider、工作流、存储、媒体、平台适配器及来源模型定义 |
| `config/*-plugins.json` | 后端适配器、业务、浏览器、桌面、模型五类插件目录 |

默认后端 **36 个激活插件、52 项服务**（包括宿主），前端 **11 个插件**；桌面为 1 个本地工作区插件加 1 个平台宿主。14 个 Provider 插件承载 26 个处理器；87 项模型定义分布在 12 份来源贡献中，构建时生成聚合目录。

## 配置

已接入移动云 MoMA：在「设置 → 闭源服务 → 移动云 MoMA」保存非 Token Plan API Key，可使用文本/视觉、图片、视频和语音模型。详见 [移动云接入说明](docs/移动云MoMA接入说明.md)。

已接入 Work-Fisher 固定模型目录：在设置中保存 API Key 后，可直接在 Agent、画布节点和默认模型中选择上游仓库已适配的文本、图像、视频、音频及音乐模型。应用不读取账户模型列表，也不提供模型添加/删除入口。详见 [Work-Fisher 接入说明](docs/Work-Fisher接入说明.md)。

指定模型已接入：文本 **GLM-5.3-Flash**（思考始终开启）、图像 **Qwen-Image-2.0-Pro**（文生图与图片编辑）、视频 **MiniMax-H3**（768P 与 2K 均为 5–15 秒；文生/首帧/尾帧/首尾帧/多模态参考）。三者共用移动云来源密钥，MiniMax 两档均以 `minimax/minimax-h3` 调用独立的 `/v1/videos` 任务协议。

画布节点的模型选择器只显示该节点类型下已配置的模型来源；没有配置时提示先连接来源。支持插件新增模型，不再受旧的常用模型白名单或价格档位折叠限制。模型选择器、文本/图片/视频/音频节点和图片工具生成按钮均不显示价格或积分估算。

Seedance 2.0 使用移动引擎 HTTPS REST 接口，支持文生、首帧、首尾帧和多模态参考；需开通对应模型权益。参考素材在视频高级设置中填写公网或已审核 asset 地址，详见 [Seedance 2.0 接入说明](docs/移动云Seedance2接入说明.md)。

编辑 [config/plugins.json](config/plugins.json) 后重启。关闭 Agent 的前后端，同时保留画布与提示词功能：

```json
{ "disabled": ["ui.agent", "module.agent"], "options": {} }
```

可以禁用 `provider.openai` 等模型来源。前项目官方账号、反馈、管理后台、上报、更新、中转和宣传功能已从实现中删除，见 [移除清单](docs/Nako线上功能清单.md)。Nako 自有更新源由发行者单独配置。必需依赖不能单独关闭：宿主会明确报错，不会偷偷重新启用。

本地工作区为当前 Electron 宿主的必需服务，由 `config/desktop-plugins.json` 装配，不使用上述禁用列表。UI、业务与存储插件使用重启生命周期；空闲 Provider 支持通过 `/api/plugins/:id/disable`、`enable` 在本次进程中启停，运行时修改不会写回配置。

## Skill 管理

启动时会把 `modules/agent/server/agent/builtin/presets` 下的 15 项 Skill 初始化到当前用户的私有技能目录，随后按普通用户 Skill 管理。已有副本不覆盖，删除后重启不恢复；不同用户的分类、文件和删除状态独立。详见 [用户级 Skill 预设](docs/用户级Skill预设说明.md)。

左侧「SKILL 管理」和 Agent「切换技能」使用同一个技能目录，按文本创作、图像设计、视频制作、音频处理、工作流等类别筛选，不再区分“官方推荐”和“我的 Skill”。可搜索名称、描述或斜杠指令。

- 添加：导入 `SKILL.md` 文件或包含它的文件夹，也支持选择包含多个技能的目录。分类默认读取 frontmatter 的 `category`；没有分类时归入“其他”，也可在导入前填写分类。
- 分类：每张卡片可以选择已有分类或输入自定义分类，点击「保存分类」生效。
- 展示：所有技能统一使用名称、描述、斜杠指令、分类与文件数量的文字卡片，没有来源专属封面、教程或添加入口。
- 删除：所有技能都提供卡片内的删除确认，重启后保持删除状态；不提供“添加预置”或恢复接口。新增技能统一通过文件或文件夹导入。

增删后对话选择器与 `/技能名` 菜单同步更新。删除不会清空已有对话，也不会中断已经开始的运行；空闲对话自动取消已删除技能的选择。导入内容只作为提示上下文，不会执行其中的脚本或获得预置制作流程的权限。

保存分类和删除后的列表刷新会恢复合适的输入焦点；后台取消失效技能不会聚焦 Agent 输入框，关闭管理窗口后可继续正常输入。

## Agent Harness

在画布「设置 → 闭源服务 → 默认模型」中，可分别设置文本、图像、视频和音频默认模型，选项仅包含已配置的来源。设置保存在本机；Agent 选择「使用默认文本模型」、新建画布节点，以及未指定模型的生成、提示词和分镜请求共用这些设置。明确选择的模型优先，已有节点与已确认批次不会随默认值改变；默认模型未设置或不可用时会提示配置，不会自动换来源。首次加载此功能需完整退出并重启桌面项目。详见 [统一默认模型说明](docs/统一默认模型说明.md)。

Agent 已改用 pi-agent-core 0.85.1，使用 `/api/agent/v2` 事件协议和独立 v2 会话树。支持受控工具、运行停止、回执去重、分支与上下文压缩。模型统一使用已配置的模型服务，Codex Agent 与外部配对连接已删除。旧聊天运行器、旧会话读写和 `/api/chat` 已移除，旧会话文件保留但不加载。

生成确认、授权卡片及工具进度穿插在触发它们的消息之后，例如「生成要求1 → 确认1 → 对话 → 生成要求2 → 确认2 → 后续对话」。卡片状态在原位置更新，重新打开会话仍保持顺序；已完成的工具记录默认折叠。输入区可选择「每次生成前确认」（默认）或「直接执行」；直接执行仅用于本项目会话的新批次，仍保留配置校验、执行记录与防重复提交，历史批次不会自动重跑。费用按模型服务商账单结算。

输入区也提供会话思考开关和强度选择，设置随项目助手草稿保存。只发送当前模型支持的参数：移动云 GLM-5.3-Flash 要求开启思考，可选低／高／最高强度；Qwen 可开关思考，强度由模型决定；豆包按其支持的档位映射开关与强度。

架构、协议、数据结构、插件关闭方式和验证边界见 [Agent Harness 重构说明](docs/Agent-Harness重构说明.md)。

## 桌面安装包

Windows 构建：`npm run desktop:package:win`；macOS 构建：在 Mac 上运行 `npm run desktop:package:mac`。产物位于 `release/`，包含运行环境及媒体组件。

完整平台、签名与数据目录说明见 [桌面应用打包说明](docs/桌面应用打包说明.md)。

设置左下角显示当前版本，可点击检查更新。桌面版支持自动检查和下载、手动确认重启安装；默认未配置更新源，不会联网检查。配置自己的 HTTPS 发布目录及发布步骤见 [自动更新配置说明](docs/自动更新配置说明.md)。
