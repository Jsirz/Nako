# Nako 桌面应用打包

提供 Windows x64 安装程序与 ZIP，以及 macOS Apple Silicon / Intel 的独立 DMG 与 ZIP 构建。使用时无需安装 Node.js、npm 或 FFmpeg；第三方模型需要用户自行配置 API Key。本地 ComfyUI、Dreamina、LibTV 等可选工具不随包分发，其中 Dreamina 自动安装目前只支持 Windows x64。

## 构建

Windows 打包还使用系统 .NET Framework 4.x 的 C# 编译器（`%WINDIR%/Microsoft.NET/Framework64/v4.0.30319/csc.exe`）构建独立更新程序，不需要额外安装 npm 运行时依赖。打包脚本将产物写入 `.packaging/app/modules/desktop-shell-observability/desktop/windows/NakoUpdate.exe`，随主应用分发；缺少编译器会使打包失败，避免发布不能执行独立更新的成品。桌面冒烟检查会核对该可执行文件存在。

Windows 应用内更新会显示独立安装阶段窗口，窗口可见后主应用才退出；安装期间关闭更新窗口会最小化到任务栏，失败时恢复显示错误。修复此窗口显示行为需要重新运行 `npm run desktop:package:win` 并安装新包。正在运行的旧安装版使用其自身携带的更新逻辑，仅上传目标新包不能改变这一次更新的窗口行为；安装修复版后的后续更新才会生效。

```sh
npm ci
# Windows x64
npm run desktop:package:win
# macOS：使用与目标 CPU 一致的 Node.js（arm64 或 x64）
npm run desktop:package:mac
npm run desktop:smoke
```

打包脚本重建画布、启动页、模型目录和图标，在 `.packaging/app` 安装锁定的生产依赖，验证 SQLite / Sharp 原生模块，随后调用 electron-builder。后台使用 Electron utilityProcess，不携带独立 Node.exe。FFmpeg / ffprobe 随应用分发，下载时校验固定哈希。Windows 使用既有固定版本；macOS 从固定版本的 `@ffmpeg-installer/darwin-*`、`@ffprobe-installer/darwin-*` 包提取静态二进制，随附上游许可证和说明。

脚本按白名单复制代码、插件与资源，不复制 `.desktop-dev`、用户项目、凭据、日志、`.verification` 或开发者 `.env`。发行包的 `.env.example` 由固定无凭据默认值生成。仅重建 `.packaging/app` 和发行构建产物，不删除用户数据。

输出位于 `release/`：

| 平台 | 输出 |
| --- | --- |
| Windows x64 | `Nako-1.0.0-windows-x64-setup.exe`、`Nako-1.0.0-win-x64.zip` |
| macOS Apple Silicon | `Nako-1.0.0-mac-arm64.dmg`、`Nako-1.0.0-mac-arm64.zip` |
| macOS Intel | `Nako-1.0.0-mac-x64.dmg`、`Nako-1.0.0-mac-x64.zip` |

每个平台另有 `SHA256SUMS-<win或mac>-<架构>.txt`。安装后的应用名和快捷方式为“Nako 画布”。Windows ZIP 解压整个目录后运行 `Nako 画布.exe`；DMG 打开后将 `Nako 画布.app` 拖入 Applications。发行文件名仍使用 `Nako-版本号-平台-架构`。

## 自动构建与签名

`.github/workflows/desktop.yml` 在推送 `main` 或手动运行时构建 Windows x64、macOS Intel x64 和 Apple Silicon arm64；Pull Request 执行三平台检查与测试。推送与项目版本一致的 `v<版本号>` 标签时，三个平台全部通过测试和成品验证后自动发布私有 GitHub Release。构件包含安装包、自动更新元数据和校验文件。客户端保留 `config/desktop-updates.json` 中的更新地址，仓库变量 `NAKO_UPDATE_URL` 可覆盖该地址；未设置或为空时沿用项目配置。GitHub 发布不自动上传到现有更新服务器。完整操作与签名 Secrets 见 [GitHub 发布说明](GitHub发布说明.md)，更新部署见 [自动更新配置说明](自动更新配置说明.md)。

当前 Windows 构建机只能生成并实测 Windows 成品；macOS DMG 必须在 macOS 主机或上述 runner 中生成并验证。仓库中配置了 macOS 构建不代表已经产出或验证了 DMG。

默认包没有受信任的开发者签名，也没有 Apple 公证。正式分发时，由发行者通过 electron-builder 的 `CSC_LINK` / `CSC_KEY_PASSWORD` 配置证书；macOS 公证另外配置 `APPLE_ID`、`APPLE_APP_SPECIFIC_PASSWORD`、`APPLE_TEAM_ID`。凭据应存放在 CI Secrets，不能写入源码。macOS 包包含 hardened runtime 权限声明，媒体工具纳入签名列表。未签名 Windows 应用可能显示 SmartScreen 提示；未公证 macOS 应用可能被 Gatekeeper 阻止。

## 本机数据

- Windows：`%LOCALAPPDATA%\Nako\data`（项目与配置），`%LOCALAPPDATA%\Nako\Desktop`（桌面状态）。
- macOS：`~/Library/Application Support/Nako/data` 与 `~/Library/Application Support/Nako/Desktop`。
- Windows API Key 使用 DPAPI 加密；macOS 使用钥匙串保存随机加密密钥，文件内容使用 AES-256-GCM 加密。
- 测试可通过 `NAKO_DESKTOP_DATA_ROOT` / `NAKO_DESKTOP_STATE_ROOT` 使用独立目录；源码开发仍使用 `.desktop-dev`。安装版不会自动迁移源码开发数据。
- 卸载不会主动删除项目与凭据。关闭窗口沿用隐藏到托盘的行为，选择托盘“退出”才会停止后台。

## 成品验证

`npm run desktop:smoke` 启动 `release/` 中的真实 Electron 成品，使用独立测试目录，检查启动页、配置接口、新建项目、Skill 存储、内置 FFmpeg、视频上传及 ffprobe 元数据、重启后媒体读取。Windows 还使用假 Key 验证 DPAPI 加密存储和重启读取，不发起模型调用。结果和截图写入 `.verification/packaged-<平台>-<架构>/`。

macOS 钥匙串适配另有加密、篡改拒绝和缺失密钥测试；这些自动测试使用模拟钥匙串，不能代替真机钥匙串授权测试。
