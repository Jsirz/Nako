# 功能分析与插件化重构对照

依据《画布开发技术文档.docx》的 12 模块划分实施。此前版本只是把部分适配器接入宿主，画布与业务仍保留在原目录。本次将 490 个业务/入口/维护文件按所有权迁出，删除了顶层 `src/`、`server/`；构建、运行、测试均指向本仓库的新位置。

“不引用旧项目文件”指不再通过路径、兼容壳或加载器读取原 Nako 项目及旧源码树。模块包含迁移并改造后的业务实现，保留来源声明，不代表所有实现均重新编写。`.verification/` 是不参与运行和构建的本地迁移快照与脚本。

## 功能与所有权

| 模块 | 功能及实现归属 | 激活入口 |
| --- | --- | --- |
| contracts | 公共类型、Canvas 操作协议、错误、工作流校验协议 | 无平台依赖的公共库 |
| kernel | 版本/依赖检查、服务与事件、权限、延迟导入、失败回滚、路由贡献 | `index.js`、`application.js`、`lazyPlugin.js` |
| canvas-ui | 节点、选择、连线、分组、拖拽、布局、剪贴板、撤销、编辑器与画布根 | `browser.ts`、`rootPlugin.tsx` |
| project | 文件夹、保存/导入/导出、修订冲突、恢复点、自动保存与工作区路径 | `browser.ts`、`serverPlugin.js` |
| asset-media | 媒体展示、上传/导入、收藏、缩略图、图片编辑、裁剪、音视频处理与回收 | `browser.ts`、`serverPlugin.js`；媒体适配器 |
| generation-core | 模型目录、来源选择、参数、并发、任务回执、超时/取消、结果恢复 | `browser.ts`、`registryPlugin.js`、`serverPlugin.js` |
| generation-providers | Provider 公共调用协议、凭据范围与恢复适配 | `index.js`；服务商实现位于 `plugins/providers` |
| workflow-runtime | 工作流定义、参数绑定、部署、执行、快照、恢复、清理与节点 | `browser.ts`、`registryPlugin.js`、`serverPlugin.js` |
| agent | 会话、多媒体引用、画布控制、Drama、Skill、分镜、提示词 | `browser.ts`、`serverPlugin.js`；提示词另用 `promptPlugin.ts`、`promptServerPlugin.js` |
| local-runtime | ComfyUI、GPU/扩展检测、本地进程、Dreamina/LibTV CLI 等 | `browser.ts`、`serverPlugin.js` |
| identity-account | 本地用户/偏好/外观、工作区隔离、第三方密钥；不含云账号 | `browser.ts`、`serverPlugin.js`、`desktopPlugin.mjs` |
| desktop-shell-observability | 本机日志、诊断、后端重连与平台装配辅助 | `browser.ts`、`serverPlugin.js` |

组件代码在所属模块的 `ui/` 中，HTTP 和业务逻辑在 `server/` 中，桌面实现位于 `desktop/` 中。这些是各模块拥有的实现目录，不是指向旧项目的兼容入口。

## 实际拆分

1. 后端启动器不再创建全部业务对象。9 个业务插件分别创建路由和服务，通过 `http.routes` 贡献路由。严格请求体限制在公共 JSON 解析器之前挂载；静态媒体在业务路由之后挂载。失败回滚撤销贡献。
2. 前端从目录延迟加载 11 个插件，最后取得 `ui.root` 挂载 React。Agent 自己注册 `ui.agent.surfaces`，画布读取可选面板；禁用后不显示聊天面板与按钮。提示词编辑和服务有独立插件。
3. 桌面从目录加载本地工作区服务 `desktop.identity`；保留历史服务名以兼容装配，但实现只读取本机工作区，无账号认证或网络请求。
4. 适配器通过服务注册表接入。提示词/分镜调用当前激活的 Provider；工作流部署与 WebApp 导入使用工作流插件的客户端工厂，不直接导入具体实现。
5. 85 个模型拆到 12 份来源贡献的 `models.ts`，由 `config/model-plugins.json` 声明。构建生成前端聚合和后端快照，不再维护单一 `modelConfig.ts`。新增移动云插件提供文本、图片、视频与语音能力，见 [接入说明](移动云MoMA接入说明.md)。
6. 跨模块静态依赖只能使用公开 `api/`、契约或声明入口。`exports.json` 列出公开接口，架构脚本校验清单、路径与模块边界。API 重导出指向本模块拥有的实现。

## 插件组成

后端默认 36 个激活项：14 个 Provider、3 个工作流执行器、3 个存储、2 个媒体、2 个平台、2 个核心注册表、9 个业务插件以及 1 个运行宿主，共 52 项服务。

Provider 包括 OpenAI、豆包、DeepSeek、GLM/Kimi、阿里云、Grok、Kling、Mureka、即梦、RunningHub、SeedVR2、Dreamina、LibTV。执行器为本地 ComfyUI、RunningHub 工作流、RunningHub WebApp。

## 数据与生命周期

SQLite 表结构、项目 JSON 和任务记录保留。旧官方中转模型不再可调用，原 Drama 场景预设停用；不会自动把旧付费任务改投其他服务。用户数据没有随源码目录搬迁，仍由运行时工作区配置定位。

宿主按依赖顺序激活，失败清理本次启动的服务、订阅和已登记资源；退出按逆序释放。Provider 有请求在执行时拒绝普通卸载。UI、业务、工作流和存储标记 `reloadRequired`，通过配置加重启启停，未承诺任意功能无损热插拔。

画布编辑、项目和提示词等是默认根插件的必需依赖。Agent 与后端重连提示为可选项。静态公共工具与类型可以跨模块复用；插件化不意味着不存在依赖。当前不提供独立安装包、插件市场或第三方进程隔离。

验收详情见 [验证记录](验证记录.md)。付费模型、本机 GPU 和完整创作流程需要对应环境的进一步验收。


官方联网功能的删除范围、第三方联网边界与迁移行为见 [移除清单](Nako线上功能清单.md)。
