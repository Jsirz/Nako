# 模块化开发

## 一、12 个功能模块

### 1. contracts：公共协议与类型

**职责：**

- 节点类型
- 生成请求/结果
- 工作流格式
- 媒体资源格式
- Agent 操作协议
- 插件 Manifest
- 错误码和事件定义

**依赖规则：**

- contracts 不依赖任何业务模块
- 这是整个插件系统的稳定 API，优先级最高

### 2. kernel：核心运行时和插件宿主

**职责：**

- 插件注册、加载、卸载
- 插件生命周期
- 服务注册表
- 事件总线
- 配置读取
- 日志和错误处理
- 能力发现
- 版本兼容检查

**核心接口可以类似：**

```ts
interface NakoPlugin {
  id: string;
  version: string;
  type: PluginType;
  activate(context: PluginContext): Promise<void> | void;
  deactivate?(): Promise<void> | void;
}
```

kernel 只依赖 contracts，不依赖具体 Provider、SQLite 或 ComfyUI。

### 3. canvas-ui：画布和界面

**职责：**

- 画布渲染
- 节点显示
- 拖拽、缩放、选择、连接
- 面板和对话框
- 用户交互状态

**这个模块不应直接依赖：**

- OpenAI、豆包等 Provider
- SQLite
- 文件系统
- ComfyUI 客户端

它应该只调用 kernel 提供的应用服务和 contracts 定义的数据结构。

### 4. project：项目和工作流文档

**职责：**

- 项目创建、打开、保存、删除
- 文件夹
- 版本号
- 冲突合并
- 恢复点
- 项目导入导出

**建议定义：**

```ts
interface ProjectRepository {
  get(id: string): Promise<Project | null>;
  save(project: Project): Promise<SaveResult>;
  delete(id: string): Promise<void>;
}
```

SQLite 只是该接口的一个实现。

### 5. asset-media：媒体资源与媒体处理

**职责：**

- 图片、视频、音频资源
- 上传、导入、删除
- 缩略图
- 裁剪、拼图、标注
- 音视频帧
- 下载和本地化

**应拆成两个接口：**

```ts
interface MediaStore {
  save(input: MediaInput): Promise<MediaAsset>;
  read(id: string): Promise<MediaAsset>;
  remove(id: string): Promise<void>;
}

interface MediaProcessor {
  crop(input: CropInput): Promise<MediaResult>;
  trimVideo(input: TrimInput): Promise<MediaResult>;
}
```

当前 `mediaAssetRouter` 直接操作 fs 和目录结构，需要逐步移除这种耦合。

### 6. generation-core：生成任务核心

**职责：**

- 生成请求标准化
- 任务调度
- 并发控制
- 超时
- 取消
- 任务恢复
- 结果保存
- 计费和授权校验

这个模块应该只依赖：

- `GenerationProvider`
- `GenerationTaskStore`
- `GenerationCoordinator`

而不应该直接知道 OpenAI、RunningHub 或 Kling 的具体实现。

### 7. generation-providers：模型 Provider 插件

这是插件化的重点。每个模型服务商独立为一个插件：

- `plugins/providers/openai/`
- `plugins/providers/doubao/`
- `plugins/providers/kling/`
- `plugins/providers/runninghub/`
- `plugins/providers/mureka/`
- `plugins/providers/dreamina/`

**统一接口：**

```ts
interface GenerationProvider {
  id: string;
  capabilities(): ModelCapability[];
  generateImage(request: ImageRequest, ctx: ProviderContext): Promise<Result>;
  generateVideo?(request: VideoRequest, ctx: ProviderContext): Promise<Result>;
  generateText?(request: TextRequest, ctx: ProviderContext): Promise<Result>;
}
```

核心层不再直接 import 具体服务商。

### 8. workflow-runtime：工作流执行插件

**职责：**

- 工作流定义
- 参数绑定
- 本地 ComfyUI
- RunningHub
- 工作流执行
- 输入输出快照
- 恢复和清理

**可定义：**

```ts
interface WorkflowExecutor {
  id: string;
  canExecute(definition: WorkflowDefinition): boolean;
  execute(request: WorkflowRunRequest): Promise<WorkflowRunResult>;
  cancel?(runId: string): Promise<void>;
}
```

**具体实现：**

- `LocalComfyExecutor`
- `RunningHubWorkflowExecutor`
- `RunningHubWebAppExecutor`

它们都是执行器插件。

### 9. agent：Agent、Codex、Drama、Skill

**职责：**

- 对话会话
- Canvas 操作
- Codex 连接
- Drama 规划
- Skill 管理
- Agent 工具调用

Agent 不应直接调用 SQLite、Provider 或文件系统，而应该通过以下服务操作画布和项目：

- `ProjectService`
- `GenerationService`
- `MediaService`
- `WorkflowService`

### 10. local-runtime：本地运行时集成

**职责：**

- ComfyUI 发现和启动
- GPU 探测
- Dreamina CLI
- LibTV CLI
- FFmpeg
- 本地扩展安装

该模块属于平台适配层，不应被画布组件直接 import。

### 11. identity-account：身份、账号和凭据

**职责：**

- 登录和登出
- 本地用户
- 用户工作区
- API Key 管理
- DPAPI 加密
- Relay 账号
- 用户隔离

这是安全边界，建议作为核心基础服务，不允许第三方插件直接读取凭据。插件只能通过受控的 `credentialStore.get(providerId)` 获取自己被授权的密钥。

### 12. desktop-shell-observability：桌面壳、更新和诊断

可以内部再分两个子模块：

- `desktop-shell`
- `observability-security`

**职责：**

- Electron 窗口
- IPC
- 更新
- 托盘
- 后端进程管理
- 日志
- 脱敏
- 诊断
- 崩溃恢复

## 二、目标依赖方向

目标应该是：

```text
desktop-shell
      |
      v
    kernel
      |
      v
  contracts
```

业务模块依赖 kernel 和 contracts：

```text
canvas-ui ------\\
project ---------\\
asset-media ------> kernel -> contracts
generation-core --/
agent ------------/
workflow-runtime /
```

**具体实现通过插件注入：**

- generation-provider plugins -> `GenerationProvider` contract
- workflow plugins -> `WorkflowExecutor` contract
- storage adapters -> Repository contract
- media adapters -> `MediaStore` contract

**关键规则：**

- canvas-ui 不得 import 具体 Provider
- generation-core 不得 import OpenAI、豆包等实现
- project 不得直接依赖 SQLite 类
- media 不得直接在 Router 中操作文件系统
- 插件不得直接访问其他插件的内部对象
- 插件之间通过事件和公共协议通信
- 业务模块不得通过 `window.__NAKO_*` 或 `app.locals` 获取核心服务
