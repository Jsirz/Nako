# 桌面自动更新

设置左下角显示当前 Nako 版本，点击版本检查更新。桌面安装版启动时立即异步检查（更新服务启动后的下一轮事件循环，不等待 15 秒，不阻塞应用启动），此后每 6 小时检查一次。发现稳定版后弹出提示，点击“立即更新”才下载；可以稍后在设置页开始下载。下载期间显示进度，关闭提示仍继续下载。完成后弹出“立即更新并重启”，点击后保存当前画布、停止后端任务，启动安装器并重新打开应用。普通关闭窗口、退出应用不会自动安装更新。

默认 `config/desktop-updates.json` 中 `url` 为 `null`，不会发起更新请求，设置显示“未配置更新源”。浏览器和源码开发版仅显示版本，不执行桌面更新。更新不携带模型 API Key、用户项目或会话。

## 1. 配置发布目录

将 `config/desktop-updates.json` 改为自己的 HTTPS 根目录，例如：

```json
{
  "url": "https://downloads.example.com/nako"
}
```

这是示例地址，需要替换。服务器应允许无登录下载静态文件；不支持 URL 中带用户名、密码、查询参数或片段。不要填写安装包文件地址，也不要自行添加平台子目录。

也可在打包进程使用环境变量覆盖，PowerShell 示例：

```powershell
$env:NAKO_UPDATE_URL = 'https://downloads.example.com/nako'
npm.cmd run desktop:package:win
```

`NAKO_UPDATE_URL` 是构建环境变量，不从应用 `.env` 或 `.env.example` 读取；`update_url` 不是配置项。GitHub Actions 可在仓库 Settings → Secrets and variables → Actions → Variables 中添加 `NAKO_UPDATE_URL`。

配置在打包时写入成品。修改源码配置不会改变已安装的应用；首次启用时，需要手动安装这一版带有正确更新源的新安装包。之前未包含更新功能或未配置更新源的安装包无法通过本功能接收首次更新。

## 2. 发布新版本

先提高根 `package.json` 的版本号，并同步 `package-lock.json`（可运行 `npm install --package-lock-only --ignore-scripts`）。例如当前为 1.1.3，下次发布设为 1.1.4。更新器不安装同版本、低版本或预发行版。

在 Windows 执行 `npm run desktop:package:win`，在对应 CPU 的 macOS 执行 `npm run desktop:package:mac`。填写更新源后，electron-builder 除安装包外会生成更新元数据。脚本不会自动上传任何文件。

将文件上传到下列目录（根目录以第一步配置为准）：

```text
nako/
  windows-x64/
    latest.yml
    Nako-1.1.4-windows-x64-setup.exe
    Nako-1.1.4-windows-x64-setup.exe.blockmap
  mac-arm64/
    latest-mac.yml
    Nako-1.1.4-mac-arm64.zip
    Nako-1.1.4-mac-arm64.dmg
    [此构建生成的 blockmap 文件]
  mac-x64/
    latest-mac.yml
    Nako-1.1.4-mac-x64.zip
    Nako-1.1.4-mac-x64.dmg
    [此构建生成的 blockmap 文件]
```

完整上传元数据引用的安装包和 blockmap 后，最后替换 `latest*.yml`，避免用户看到未上传完的版本。保持文件名不变；校验值由构建工具生成，不手工修改。元数据建议配置 `Cache-Control: no-cache`；CDN 需要及时刷新元数据。macOS 两种架构必须分目录，不能互相覆盖同名元数据。

Windows 自动安装使用 NSIS 安装版。ZIP 主要用于便携运行；要使用受支持的自动替换安装流程，请先安装 setup.exe。macOS 自动更新依赖有效的代码签名；正式分发还应完成 Apple 公证。签名配置见《桌面应用打包说明》。更新下载会由 electron-updater 校验 SHA-512；HTTPS 发布目录应始终由发行者控制。

## 3. 验证与故障

在已经安装且配置了相同更新源的版本中，打开设置点击版本：没有更高稳定版时显示“当前已是最新版本”；有更新时提示“立即更新”，确认后显示下载进度，完成后提示重启。保存失败时不会继续重启，修复保存问题后可重试。

### Windows 独立更新窗口

点击“立即更新并重启”后，应用保存画布并停止后台任务，将轻量更新程序复制到 `%TEMP%/nako-update-<随机值>/`，确认窗口启动后才退出主应用。窗口显示“准备更新 → 安装与检查 → 重新打开”，各阶段根据实际执行状态推进，安装期间使用活动指示而非估算百分比。

更新程序等待旧应用退出，再次校验下载包 SHA-512，以 `--updated /S` 静默执行 NSIS。沿用当前安装目录和可识别的用户安装范围，不再显示“为谁安装”“安装位置”等向导页。首次手动安装保留原向导；需要提权时仍由 Windows 弹出系统授权。

安装进程成功结束并确认程序版本符合目标后，由更新程序启动应用；收到新版启动回执才结束窗口。更新程序以可见 GUI 窗口启动，窗口绘制且确认系统可见后才通知主应用退出。安装期间点击关闭会最小化到任务栏，可点击任务栏恢复查看进度；出错时恢复窗口显示错误与重试按钮，不同时启动第二个安装进程。窗口展示准备、安装与检查、重新打开三个阶段和等待动画，不显示估算的安装百分比。若安装已完成但启动失败，重试仅处理启动阶段。异常详情保存在上述临时目录的 `error.txt`。

更新窗口启动失败时主应用不会退出，并恢复后端。旧应用 60 秒内未退出时不强制杀进程，提示用户退出后重试。安装失败时不标记成功或自动启动未验证版本；无法重试时可手动运行完整安装包。更新程序不接收模型密钥或项目内容，只继承必要系统环境与显式的数据/状态目录配置。

此独立窗口用于 Windows；macOS 继续使用 electron-updater 原生安装与重启机制。本功能需要新构建的安装包；旧版更新到本版的那一次仍由旧版更新逻辑控制，安装本版后的后续更新才使用独立窗口。

“未配置更新源”：重新构建并安装带更新地址的版本。

“更新失败”：检查对应平台目录中 `latest*.yml` 是否能通过 HTTPS 下载，元数据引用的文件是否完整、哈希是否匹配、网络和证书是否正常。修复后点击“重试更新”。

本次未连接真实发布服务器，未执行真实跨版本安装，未验证 macOS 真机更新。自动更新只更新程序，用户数据继续保存在安装目录之外。
