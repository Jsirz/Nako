# 画布节点目录开发说明

画布节点统一遵循 Node SDK 2：内置节点和用户节点都由注册表提供定义，定义只描述业务能力，不读取 API Key、不导入 Provider、不直接访问文件系统或网络。宿主负责模型、媒体、项目、工作流和持久化能力，并根据节点声明授予最小权限。节点可被画布和 Agent 以同一套 DAG 运行服务执行。

## 目录与加载

运行时默认扫描安装目录下的 `nodes/`，每个直接子目录是一个节点包：

```text
<安装目录>/
└─ nodes/
   ├─ canvas-core/       # 宿主内置包
   └─ text-replace/      # 用户包
      ├─ manifest.json
      ├─ index.mjs
      └─ ui.html         # iframe 节点可选
```

源码运行默认目录是本仓库的 `nodes/`。Windows 安装版是 `<安装位置>/resources/app/nodes/`；macOS 是 `Nako 画布.app/Contents/Resources/app/nodes/`。实际目录可从 `GET /api/node-packages` 的 `directory` 查看。`NAKO_NODE_DIR` 可覆盖用户包目录，宿主仍会加载安装目录中的 `canvas-core`。

放好文件后重启应用，或调用 `POST /api/node-packages/reload` 后刷新页面；加载错误由目录接口返回。添加菜单不再显示重载操作。应用资源目录中的自定义文件可能在安装更新时被覆盖，开发时可使用独立目录覆盖并备份源码。

## Manifest

```json
{
  "id": "text-replace",
  "version": "1.0.0",
  "apiVersion": "^2.0.0",
  "title": "字符替换",
  "entry": "index.mjs",
  "capabilities": [],
  "nodes": [{
    "type": "text-replace.replace",
    "version": "1.0.0",
    "category": "utility",
    "inputs": [{"id": "text", "media": ["text"], "required": true}],
    "outputs": [{"id": "result", "media": ["text"], "required": true}],
    "parameters": {
      "type": "object",
      "additionalProperties": false,
      "properties": {
        "from": {"type": "string", "default": "旧词"},
        "to": {"type": "string", "default": "新词"}
      }
    },
    "render": {"kind": "generic"},
    "executor": {"method": "replace", "transport": "rpc", "timeoutMs": 30000},
    "agent": {"exposed": true, "sideEffect": "none"}
  }]
}
```

端口 ID 是持久化协议的一部分，创建后不能按位置重命名。支持的媒体类型为 `text`、`image`、`video`、`audio`、`json`、`any`。参数使用受限 JSON Schema；宿主会在执行前校验类型、默认值、枚举和边界。

节点包级 `capabilities` 是上限，节点级声明只能从包级列表中取值：

- `models.generate`：通过宿主默认模型或指定模型生成文本、图像、视频或音频。
- `media.inspect`、`media.read`、`media.compose`：读取当前项目媒体、抽帧和合成。
- `workflow.execute`：调用已安装工作流执行器。
- `project.read`、`storage.get`、`storage.set`：读取当前项目摘要或使用按插件、项目隔离的 64KB 键值存储。

声明能力的运行会进入授权状态；Agent 还必须满足 `agent.exposed`。写入、网络和明确要求确认的节点总是显示用户授权卡。授权卡展示节点、参数、能力和生成额度。`maxModelCalls` 为本次生成额度：文本或工作流每次占 1，批量生成占其 `count`，全图共享上限 0–100；它不是金额上限。现有 Agent 的预算授权继续由生成服务校验。基础节点的“生成”按钮以及已经通过 Agent 授权的请求沿用原确认流程；外置节点由宿主卡片确认，iframe 无法批准。批准后热重载不会替换该次运行的执行器。

## 执行器

`index.mjs` 只导出 `executors`。输入按稳定端口 ID 组织，返回值也必须按输出端口 ID 组织：

```js
export const executors = {
  replace({ inputs, parameters }) {
    const text = String(inputs.text || '');
    return { result: text.split(String(parameters.from || '')).join(String(parameters.to || '')) };
  }
};
```

执行器在独立 QuickJS 进程中运行，只有 `ctx.call(capability, input, stepId)` 和 `ctx.progress(message)` 可用。包代码不能使用 `process`、`require`、`fetch`、Node 内置模块、环境变量、宿主路径或未声明能力。仅允许包内相对 `.mjs/.js` 导入，单包最多 100 个源文件、4MB；结果最多 4MB，执行时间由 manifest 限制。该隔离限制的是宿主 API 和代码资源，不等同于操作系统级安全沙箱，因此不要加载不可信来源的代码。

模型调用示例（Manifest 必须声明 `models.generate`）：

```js
const reply = await ctx.call("models.generate", {
  kind: "text", model: "", prompt: "分析画面",
  references: [{ type: "image", url: "/library/media/项目ID/images/图片.png" }],
  options: { languageMode: "multimodal-chat" }
}, "analyze");
// reply.text；图像/视频/音频返回 { type, url, urls }
```

空模型使用已配置默认模型；指定模型填模型目录的完整名称。媒体引用必须属于当前项目；可先用 `media.inspect` 获取视频帧，再传给视觉模型。连接信息及密钥只由宿主凭据服务读取，参数不能覆盖模型服务地址。异步多步节点每一步使用不同而稳定的 `stepId`。

## 自定义界面

将 `render.kind` 设为 `iframe` 并声明 `render.entry`：

```json
"render": {"kind": "iframe", "entry": "ui.html"}
```

页面必须为自包含 HTML，脚本与样式内联，最大 1MB。React/Vue 等也应先构建为单文件页面。页面通过 `postMessage` 使用协议 `nako.node-ui/1`：先发送 `ready`，宿主发送 `state`，页面发送 `parameters`、`run` 或 `cancel`。iframe 只有 `allow-scripts`，禁止网络、表单、父页面访问和外部资源；页面不能直接授权或调用模型。

```js
let channel;
addEventListener("message", event => {
  if (event.source !== parent || event.data.protocol !== "nako.node-ui/1") return;
  if (event.data.type === "state") { channel = event.data.channel; /* 更新 parameters/run */ }
});
const send = (type, value) => parent.postMessage({ protocol: "nako.node-ui/1", channel, type, value }, "*");
send("ready");
// send("parameters", { from: "旧词", to: "新词" });
// send("run"); // 只准备运行，授权由宿主处理
```

## 版本迁移与缺失节点

升级端口或参数时在节点定义中加入声明式 `migrations`，例如 `renameInputs`、`renameOutputs`、`renameParameters` 和 `defaults`。运行服务会同时迁移 DAG 连线、隐式 `inputLinks` 和初始输入。找不到包或迁移链时保留原始节点数据：缺包显示占位，缺少迁移链显示迁移错误并阻止运行；不会静默删除连线。

## 运行与 Agent

画布运行使用 `POST /api/node-runs`、`GET /api/node-runs/:id`、`POST /api/node-runs/:id/approve` 和 `POST /api/node-runs/:id/cancel`。同一 `projectId + requestId` 的重复提交返回原运行记录；同一节点能力调用必须使用稳定 `stepId`，未知结果不会自动重放。关闭 Agent 面板只会断开前端观察，后端继续写入运行存储；关闭项目或应用时才停止运行。重新打开会话或画布会按运行 ID 拉取最新状态。

Agent 先调用 `nodes` 获取公开节点和参数/端口，再用项目的 `node:${revision}` 调用 `runNode`。后端重新校验插件归属、Agent 暴露标记、项目版本、端口类型和能力授权。节点结果作为工具活动写回对话时间线，不需要浏览器桥接。

### 内置节点与扩展边界

`nodes/canvas-core` 承载文本、图像、视频、音频、上传引用、拼图及工作流执行器。模型执行也经过隔离能力桥。基础节点可引用宿主 `native` 渲染器，用户目录只允许 `generic` / `iframe`；这是 UI 接入权限差异，不会额外授予模型凭据或文件系统权限。原生编辑器仍负责专用媒体交互及 ComfyUI 工作流编辑；外置节点无需修改这些组件。

`workflow.execute` 调用现有已注册工作流及其校验、部署绑定和执行器，不允许传任意脚本。完整 DAG 是当前节点注册表的有向无环图，最多 500 节点 / 2000 边 / 16 并行节点；环或缺失端口在提交前失败。后台运行结果存于数据目录的 `private/node-runs`，不写入节点源码目录。应用重启会把未完成运行标为 `interrupted`，不会自动重做可能已扣费的步骤。

## 逐帧拉片与测试夹具

`nodes/canvas-core/shotAnalysis.mjs` 是正式内置的逐帧拉片执行器，使用 `media.prepareAnalysis`、`models.generate`、`media.validateAnalysis`、`media.extractAnalysis` 和受限存储能力。节点支持上传视频或连接已有视频节点，选择分镜、动态、声音后点击开始，保存完成即自动批准并执行本次任务，不展示二次授权卡；首次分析模型预算为 1，仅重新提取为 0。底层仍使用 `Qwen 3.8 Max · Work-Fisher`，UI 隐藏模型标识；凭据由宿主已有设置解析，包代码不读取密钥，内核能力和快照校验保持生效。

原始视频保留本地，上传最长 20 分钟、最大 45 MiB 的分析代理视频；校验模型 JSON 后从原视频提取 1～3 张关键帧、镜头片段和混合原声音轨。时间戳是模型估计，可在折叠结果详情的 JSON 中调整后重新提取；不会分离对白与配乐。分析及重提取成功后直接按镜头成组进入画布，无需再次确认；同一结果按源节点及分镜标识去重，重新分析产生新结果。卡片使用圆角视频预览、时长/尺寸、青色维度按钮和整行开始按钮。`nodeDirectRunRequestId` 记录本次执行意图，支持节点重新挂载后恢复原任务，终态消费，普通历史结果不会自动插入。网络结果未知时查询原任务，不重新提交。预览模式仅展示，不查询或启动运行。复制、预设和导入保留结果但清除本地运行缓存及执行意图，需重新分析才能再次提取；未插入的历史或导入结果保留手动添加入口。

`examples/` 的旧开发示例已移除，隔离运行和冒烟测试所需的最小字符替换包移到 `tests/fixtures/nodes/text-replace`，不自动安装。逐帧拉片协议及交互回归位于 `tests/shot-analysis.test.js` 和 `tests/shot-analysis-ui.test.js`；`tests/shot-analysis-media.test.js` 在存在 bin 下 FFmpeg/FFprobe 时执行真实编解码，已在 Windows 本地通过。当前上游 `qwen/qwen3.8-max` 的视频输入/声音理解能力及双平台成品尚需真实服务与真机确认，模拟请求通过不等同上游支持已验证。

节点包变更后运行：

```powershell
npm.cmd run unit -- tests/node-sdk.test.js tests/node-runtime.test.js
npm.cmd run check:architecture
npm.cmd run typecheck
```

## 隔离进程错误排查

桌面节点的受信任启动脚本使用字符串绝对路径启动，Electron 下显式启用 Node 模式，macOS 优先使用 Helper 可执行文件。节点包业务代码仍在 QuickJS 中运行，不能直接读取进程环境、模型凭据或文件系统。

若出现“节点隔离进程退出”，界面会附带退出码及信号（如果有）；宿主日志包含 `[desktop-shell-observability] Node sandbox failed`，记录插件、执行方法、运行/节点 ID、退出码、信号及最多 8192 个字符的子进程错误尾部。原始错误输出不放入前端提示。正常完成、取消及超时后的进程清理不记录成异常退出。

macOS 安装版默认查看 `~/Library/Application Support/Nako/data/logs/backend.stderr.log`。使用自定义数据目录时查看该目录下的 `logs`。修复需要重新打包安装；用户节点包无需更改。

## 已提交生成任务的结果恢复

基础生成节点的外层运行和内部模型任务使用不同标识。状态查询会通过宿主 `generation.runtime.observeNode`，按原运行/步骤派生的任务标识和项目归属，只查询原服务商任务并保存结果，不重新生成。

单个 `nako.canvas-core` 文本/图像/视频/音频节点、且仅有一个 `models.generate` 步骤时，可将已确认结果回填到节点运行和画布；是否能查询远端取决于原服务商的恢复能力。待核对状态保留任务标识和 `recoveryPending`。自定义节点或多步图不自动重新执行，以免重复产生费用。已失去画布任务标识的观察中断记录，会尝试从同一项目/节点的近期运行中找回最新未确认记录；缺失原持久化记录时不能凭提示文字恢复。

观察结果必须通过原任务身份及凭据检查；取消/关闭后不会把正在结束的查询回填为节点成功。恢复不会增加授权预算，也不会恢复执行下游业务代码。
