# 插件开发说明

插件 API 为 `1.0.0`，契约见 `modules/contracts/index.d.ts`，宿主见 `modules/kernel/index.js`。新增实现必须属于明确模块或适配器，不能新增旧 `src/`、`server/` 兼容目录。

## 装配目录

| 文件 | 内容 | 路径基准 |
| --- | --- | --- |
| `config/backend-plugins.json` | Provider、执行器、存储、媒体、平台与核心注册表 | 相对于目录文件 |
| `config/application-plugins.json` | 8 个后端业务插件 | 相对于目录文件 |
| `config/browser-plugins.json` | 11 个 UI 插件 | 相对于 `apps/canvas` |
| `config/desktop-plugins.json` | 本地工作区桌面插件 | 相对于目录文件 |
| `config/model-plugins.json` | 模型定义贡献 | 相对于目录文件 |

运行插件有 `id`、`entry`、`manifest`。后端工厂插件另声明 `factory`、`options`，凭据授权由宿主目录的 `credentialKeys` / `credentialGrants` 控制。模型贡献使用 `entry` 和 `exports`。

宿主先读取 Manifest，再在激活时导入实现；实现中的 Manifest 必须完全匹配。禁用项只注册元数据，不激活实现。

## 最小插件

```js
export default {
  manifest: {
    id: 'example.echo', version: '1.0.0', apiVersion: '^1.0.0', type: 'module',
    services: { provides: ['example.echo'] },
  },
  activate(context) {
    context.services.register('example.echo', { echo: value => String(value) });
    context.events.on('project.opened', event => { /* 消费公共事件 */ });
    context.onDispose(() => { /* 释放本插件创建的资源 */ });
  },
};
```

用 `dependencies` 声明依赖插件，用 `services.requires` 声明必需服务，使用 `context.services.get()` 取得实现。重复 ID/服务、未声明访问、循环/缺失依赖、版本不兼容均报错。版本范围支持精确版本、`^x.y.z` 和 `>=x.y.z`。

## 后端业务

使用 `defineApplicationPlugin`，自动依赖 `host.runtime` 并声明 `http.routes`。在 `activate` 内创建服务和路由，不能在模块导入时启动进程或注册路由：

```js
export default defineApplicationPlugin({
  id: 'module.example', provides: ['example.info'],
  activate(context) {
    const router = express.Router();
    const info = { version: context.services.get('host.runtime').version };
    router.get('/api/example', (_request, response) => response.json(info));
    context.services.get('http.routes').contribute(context, router);
    context.services.register('example.info', info);
  },
});
```

路由阶段：`10` 为自己的严格请求体解析器，`20` 为普通 JSON 路由，`30` 为静态文件；`order` 控制同阶段顺序。请求先经过宿主认证边界，路由贡献随激活失败或关闭撤销。

## Provider 与模型

1. 参照 `plugins/providers/openai` 建立 `manifest.json`、`index.js`、`implementation.js`；入口使用 `defineProviderPlugin`。
2. 在 `config/backend-plugins.json` 登记入口、Manifest 与宿主允许的凭据。
3. 模型放入本来源 `models.ts`，在 `config/model-plugins.json` 声明导出列表。用唯一模型名和 `catalogOrder` 保持排序。
4. 运行 `npm.cmd run build:model-catalog`，生成 `modules/generation-core/models/catalog.ts` 和后端 `modelCatalog.generated.json`。不要手改生成文件。

`GenerationProvider` 为 `{ descriptor, handler }` 契约。descriptor 必须声明 `name/kinds/execution/requiredSecrets`，与 manifest 的 `providers[]` 一致；每个 kind 实现 `generate*`，异步恢复必须成对实现 `canRecover*`/`recover*`。适配层只发布这些方法、`id` 和 `capabilities`。密钥只读 `context.credentials.get(manifest.id)`，来源配置只读宿主 config，不接受调用方配置回退。

模型贡献只能指向本插件 `models.ts`，模型的 Provider 和媒体类型必须与 manifest 一致；构建禁止数据贡献依赖 Provider 实现或外部运行库。工作流公开方法和客户端白名单集中在 `contracts/pluginValidation.js`，执行器及客户端在插件关闭后失效。

媒体存储经 `media.operations` 调用；`library` 和 `downloads` 子服务分别承接素材库和本地下载。Router 只负责 HTTP 转换，不能导入 fs/path/child_process。新素材上传使用 `/api/assets/upload/:type` 或本地文件导入接口，旧 JSON Base64 上传入口已删除。

业务从 `generation.providers` 发现处理器，每次调用解析当前激活实现；提示词/分镜也不能绕过禁用状态导入 Provider 文件。适配层限制凭据范围，保留 `generate*`、`recover*`、`canRecover*` 语义。协议实现留在插件内；来源展示、凭据白名单、任务恢复和 Agent 兼容名单仍需按能力登记。

完整示例可参照 [移动云 MoMA 插件](移动云MoMA接入说明.md)：四类处理器共用来源密钥，视频使用异步任务恢复。新增密钥登记到 `modules/contracts/providerSecrets.js`，桌面运行时直接复用该名单；来源设置及 Agent 仍使用独立显式登记，不能仅添加模型目录。

较大的纯模型数据可在 `config/model-plugins.json` 的 `data` 中声明插件自身 `catalog/*.json`。构建器只接受这些显式列出的 JSON 数组，仍禁止导入运行时实现。参见 [Work-Fisher 固定模型目录](Work-Fisher接入说明.md)。

需要在画布手填参考素材地址的模型，可声明 `referenceUrlParams`，将 `image/video/audio` 映射到相应高级参数名，并将参数定义为 `text`。画布按空白字符拆分地址，追加在连接素材之后，统一参与模式选择与提交；Provider 仍须独立校验 URL、数量和模式。参见 [Seedance 2.0](移动云Seedance2接入说明.md)，不要让 UI 直接导入 Provider 实现。

## 工作流、媒体与存储

`defineExecutorPlugin` 向 `workflow.executors` 注册执行器和客户端工厂。业务通过 `createClient(id, options)` 获取有限客户端方法。错误类与输入校验在 `contracts/workflowProtocols.js`，业务不能导入适配器实现来做错误判断。

项目使用 `project.repository`，媒体使用 `media.store` / `media.operations` / `media.processor` / `media.editing`，Agent 使用 `agent.persistence`。保留跨项目检查、内容/大小限制和私有目录保护。不要把数据库、密钥或原始客户端对象作为不受限的公共服务返回。

## 前端与桌面

前端在 `activateBrowserModule` 中安装能力，使用 `trackBrowserResource` 登记有 `destroy/dispose` 的对象；安装器返回释放函数时显式调用 `context.onDispose(fn)`。历史 Window 字段名只用于类型兼容，运行服务存在宿主注册表中。

Agent 在自身 `ui/agent/surfaces.ts` 装配组件，注册 `ui.agent.surfaces`；画布通过可选插槽渲染，缺席时不显示按钮与面板。提示词的前后端入口独立于 Agent。根视图由 `ui.canvas-shell` 提供 `ui.root`。

桌面宿主提供 `desktop.environment`，包含平台网络、密钥保护、工作区选择、广播和进程启动；本地工作区插件提供 `desktop.identity`（历史服务名，无云端认证）。窗口和 IPC 留在宿主。工作区服务为必需，变更目录时必须提供对应本地实现。

## 边界与生命周期

跨模块共享纯函数、组件或类型，从所属模块 `api/` 导出并同步 `exports.json`；有生命周期的服务通过宿主获取。禁止跨模块引用私有实现，禁止业务直接导入适配器。生成的模型聚合是声明式数据贡献的特例。

`config/plugins.json` 的 `disabled` 控制浏览器构建和后端启动；浏览器变更需要重新构建，`desktop:dev` 自动完成。后端测试可用 `NAKO_PLUGIN_CONFIG` 指定独立配置。必需依赖被禁用时明确拒绝启动。

`reloadRequired: true` 表示通过重启启停，不能据此宣称支持无损热卸载。空闲 Provider 可在进程内启停，有活动请求则拒绝。配置不随运行时 API 的启停自动保存。

## 检查

`npm.cmd run check` 还运行 `check:local-only`，防止官方服务域名、账号/反馈/更新桥、Relay 与统计上报重新进入运行代码。它校验旧目录缺席、导入可解析、五类目录、公开 API 清单与依赖方向，并执行测试、构建和正常/禁用 Agent 两种后端冒烟。新插件补充相关行为测试，不要通过放宽边界检查接入。

这是可信代码的进程内宿主，权限检查不能阻止恶意 JavaScript 自行导入系统模块。当前不包含插件市场、独立发行包或任意第三方代码隔离。


新增 Provider 只能因用户配置或模型操作访问对应第三方服务；禁止启动时注册官方设备、同步官方账号或上报使用数据。本地诊断可以保留，网络上报不可借诊断之名恢复。

## 节点文件夹（自定义节点）

画布启动时会扫描安装目录的节点包。默认位置为：

```text
<安装目录>/nodes/
```

每个直接子目录都是一个节点包：

```text
nodes/
└─ text-tools/
   ├─ manifest.json
   └─ index.mjs       # 可选；提供执行器
```

`manifest.json` 示例：

```json
{
  "id": "text-tools",
  "version": "1.0.0",
  "apiVersion": "^1.0.0",
  "title": "文本工具",
  "entry": "index.mjs",
  "nodes": [
    {
      "type": "text-tools.prefix",
      "version": "1.0.0",
      "category": "utility",
      "title": "添加前缀",
      "inputs": [{ "id": "text", "media": ["text"], "required": true }],
      "outputs": [{ "id": "result", "media": ["text"] }],
      "render": { "kind": "generic" },
      "executor": { "method": "prefix", "transport": "rpc" }
    }
  ]
}
```

`index.mjs`：

```js
export const executors = {
  prefix({ inputs, parameters }) {
    return `${parameters?.prefix || ''}${inputs?.[0]?.value || ''}`;
  },
};
```

也可以设置 `NAKO_NODE_DIR` 指向其他目录。目录变更后调用 `POST /api/node-packages/reload`，画布会重新读取目录；前端通过 `GET /api/node-packages` 获取节点声明。菜单、通用卡片和端口连线校验都来自注册表。移走节点包后，旧项目仍会保留节点数据并显示缺失节点占位。

节点目录中的 JavaScript 是宿主进程内的受信任代码，RPC 提供方法白名单、JSON 数据大小限制和超时保护，但不是操作系统级沙箱；不要运行来源不明的节点包。

运行时默认从安装目录的 `nodes/` 读取节点包。`NAKO_NODE_DIR` 只作为显式覆盖项；Agent 节点还需要在节点定义中声明 `agent.exposed: true`，并通过 `canvas_control` 的 `nodes` / `runNode` 操作调用。
