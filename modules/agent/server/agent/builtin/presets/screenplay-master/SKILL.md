# 一、主技能流程总纲

## 1. 激活时机

**触发条件（任一满足即激活）：**
1. 用户提到"短剧/微短剧/竖屏剧/付费短剧/短剧剧本"
2. 用户要求"写剧本/写一集/写大纲/写人设/分集大纲/分镜"
3. 用户提到集数："60集/80集/100集/1分钟/3分钟/5分钟"
4. 用户提到短剧相关元素："钩子/卡点/反转/打脸/爽点/人设"
5. 用户要求"品牌短剧/宣传片剧本/短剧IP"

**负面触发器（遇到这些 NOT 激活）：**
1. 用户明确要长篇小说、电影长片、舞台剧
2. 用户只说"帮我剪个视频"而无剧本需求
3. 用户用非中文创作（如英文剧本、日语剧本）
4. 用户要求的是影视评论、观后感、剧情分析（非创作）

## 2. 首问清单（8 个必问问题）

在与用户正式开始创作前，必须依次确认以下 8 个问题，缺一项则后续流程不完整：

| # | 问题 | 目的 |
|---|------|------|
| Q1 | 目标平台是什么？（抖音/快手/微信小程序/其他） | 决定画幅、时长、节奏标准 |
| Q2 | 短格式还是长剧集？（极速1-3分钟/弧光4-6分钟 vs 60-100集） | 决定激活哪个模式 |
| Q3 | 题材类型？（男频/女频；都市/古装/悬疑/甜宠/战神等） | 决定钩子类型和爽点方向 |
| Q4 | 核心灵感或一句话梗概是什么？ | 决定故事种子和基调 |
| Q5 | 主要角色有几个？有无指定人设？ | 决定角色工程工作量 |
| Q6 | 目标受众画像？（年龄/性别/偏好） | 决定情绪节奏和语言风格 |
| Q7 | 有无品牌植入或特殊需求？ | 决定是否需要适配商业元素 |
| Q8 | 期望交付物是什么？（大纲/单集剧本/完整剧本/人设卡） | 决定流程终点 |

> **注意**：Q2 的回答决定进入**短格式模式**（引用 2.1）还是**长剧集模式**（引用 2.2）。

## 3. 双模式选择逻辑

### 3.1 模式判断条件

| 用户表达 | 模式 | 参考章节 |
|----------|------|---------|
| "1分钟短剧" "3分钟" "5分钟" "品牌宣传" "单集" "4-6分钟" "短片" "电影节" "一集" | 短格式 | 2.1 短格式剧本创作指南 |
| "60集" "100集" "系列" "连载" "付费短剧" "80集" "长篇" | 长剧集 | 2.2 长篇短剧创作指南 |

### 3.2 模式差异速查

| 维度 | 短格式 | 长剧集 |
|------|--------|--------|
| 单集时长 | 极速1-3/弧光4-6 | 1-2分钟 |
| 总集数 | 1集（独立成片） | 60-100集 |
| 结构深度 | 单集完整弧光 | 大树六段式宏观结构 |
| 钩子密度 | 极速10s/弧光15s | 每集结尾必留钩 |
| 付费卡点 | 无 | 卡一8-16 / 卡二25-30 / 卡三45-55集 |
| 适用场景 | 品牌、IP预热、短片 | 付费短剧、系列IP |

## 4. 统一 5 步工作流

无论短格式还是长剧集，均按以下 5 步执行。每步标注触发条件、负责角色、输出标准及引用文件。

### Step 0: 需求确认 → 模式选择 → 平台适配

| 项目 | 内容 |
|------|------|
| **触发条件** | 用户首次提出短剧创作需求，8问已收集完毕 |
| **负责角色** | Story Architect |
| **关键动作** | 根据Q2选择模式；根据Q1加载平台适配规则；输出《项目参数确认表》 |
| **输出标准** | 《项目参数确认表》含：模式/平台/题材/受众/集数/时长/交付物清单 |
| **引用文件** | 2.8 行业数据（字数标准、付费卡点参考）、2.9 平台差异指南（平台特征与适配策略） |

### Step 1: 角色设计（人设工程）

| 项目 | 内容 |
|------|------|
| **触发条件** | Step 0完成，需进入角色创建阶段；或用户主动要求"设计人设/角色" |
| **负责角色** | Character Engineer |
| **关键动作** | 为每个主要角色完成四件套（欲望/雷点/反差/语言标识）；输出角色关系网；标记爽点密度区 |
| **输出标准** | 每个角色一份JSON人设卡（引用 3.1 人设卡模板）；角色关系图 |
| **引用文件** | 2.3 角色工程参考手册（人设四件套、弧光、三角关系、爽点密度、反转节奏） |

### Step 2: 故事架构（大纲设计）

| 项目 | 内容 |
|------|------|
| **触发条件** | 人设完成；或用户直接要求"写大纲/写梗概/设计故事" |
| **负责角色** | Story Architect |
| **关键动作** | 短格式：设计6种开场钩子+单集完整弧光；长剧集：大树6 Phase设计，完成六段式结构+付费卡点位置 |
| **输出标准** | 短格式：《单集节拍表》（引用 3.2 节拍表模板）；长剧集：《总集大纲+Phase分阶段节拍表》 |
| **引用文件** | 短格式：2.1 短格式指南（极速/弧光流程、6种钩子、5种反转）；长剧集：2.2 长篇指南（6 Phase流程、宏观结构、循环机制）；全模式：2.5 钩子设计（黄金三秒、集间钩子、付费卡点设计） |

### Step 3: 内容创作（分集剧本）

| 项目 | 内容 |
|------|------|
| **触发条件** | 大纲已确认；用户要求"写剧本/写这一集/写第X集" |
| **负责角色** | Content Creator |
| **关键动作** | 按单集模板输出完整剧本：场景→运镜→台词→分镜指示；竖屏9:16适配；台词口语化+戏剧化。若含打斗场景，按【行动段→攻击段→受击段】三段式结构嵌入【特效：…】标注（不计入总字数） |
| **输出标准** | 每集一份完整剧本（引用 3.4 剧本模板），含：本集信息/场景/角色台词/分镜/音效/特效标注 |
| **引用文件** | 2.4 场景与台词写作（竖屏构图、运镜词汇、微表情、短句控制、潜台词）；2.6 格式规范（Fountain格式、场次编号、制作可行性检查）；2.10 VFX 特效描写（打斗场景三段式）；3.3 单集大纲模板（Step 3前置） |

### Step 4: 质量检查（交付前必检）

| 项目 | 内容 |
|------|------|
| **触发条件** | 单集或批量剧本完成，准备交付；或用户要求"检查/优化/看看有什么问题" |
| **负责角色** | Quality Inspector |
| **关键动作** | 执行7项质量门检查 + 4维度快速诊断；修复问题后重检；通过全部检查方可交付 |
| **输出标准** | 《质量检查报告》含7项Pass/Fail判定 + 修改记录；校验脚本运行结果 |
| **引用文件** | 2.7 质量门与快速诊断（7项质量门、4维度诊断、12个常见陷阱）；4.1 validate-script.py（10项自动校验功能） |

### Step 5: 循环推进（仅长剧集）

| 项目 | 内容 |
|------|------|
| **触发条件** | 当前批次（如1-10集）已完成Step 4，需继续下一批次；或用户说"继续写/下一批/后面集数" |
| **负责角色** | Story Architect + Content Creator |
| **关键动作** | 汇总已完成批次的数据（完播率反馈、观众评论），微调后续Phase节奏；按Phase计划推进下一批次 |
| **输出标准** | 每批次交付后输出《推进摘要》：已完成集数/下批计划/调整项 |
| **引用文件** | 2.2 长篇短剧创作指南（循环推进机制、Phase衔接规则） |

## 5. 核心规则 9 条（硬性约束，任何 Step 均不可违反）

| # | 规则 | 参数 |
|---|------|------|
| R1 | **节奏** | 极速模式每10秒有钩子；弧光模式每15秒有钩子；长剧集每集结尾必须有悬念钩子 |
| R2 | **钩子** | 前3秒必须有Hook（信息冲击）；每集结尾必须有悬念/情绪爆发/未完待续 |
| R3 | **台词** | 单句8-15字；口语化+戏剧化；对话如格斗，一句一招；禁止内心独白 |
| R4 | **场景** | 短格式单集≤3个场景（极速模式≤2个），长剧集单集3-5个场景；超出必须有明确创作理由 |
| R5 | **情绪** | 极端情绪交替（虐↔甜、燃↔泪、惊↔气愤）；波峰波谷整体呈上升趋势 |
| R6 | **竖屏** | 9:16画幅，人物占画面60%+；优先中景/近景/特写；背景极简化 |
| R7 | **付费点** | 长剧集卡点位置：卡一第8-16集 / 卡二第25-30集 / 卡三第45-55集 |
| R8 | **字数** | 单集字数 = 时长(秒) x 10-12字；精确范围见 2.8 行业数据 |
| R9 | **特效** | 打斗场景的【特效：…】标注不计入总字数；必须按三段式（行动→攻击→受击）完整描写；特效风格必须与角色背景一致；详细规则见 2.10 VFX 特效描写 |

> 违反任何一条 → Quality Inspector 必须标记为 Fail 并返修。

## 7. 循环推进机制（长剧集 Step 5 详解）

长剧集按**大树生长法**分批次推进，每完成一个 Phase 的集数后进入循环检查点：

```
Phase 0(种子) → Phase 1(树根) → Phase 2(树冠) → Phase 3(主干) → Phase 4(分支) → Phase 5(叶片) → Phase 6(土壤)
     ↓              ↓               ↓               ↓               ↓              ↓              ↓
   灵感孵化      主线+结构       终局锁定       骨架搭建       枝叶丰满       逐集精写       打磨校验
   (Q1-Q8)     (六段式结构)    (结局设计)    (四幕框架)     (分集大纲)      (分集剧本)      (7项质量门)
```

**循环规则：**
- 每完成 10 集（一个批次），执行 Step 4 质量检查
- 检查通过后交付当前批次，同时启动下一批次创作
- 如有观众数据反馈（完播率/评论），在下一批次启动前微调节奏和钩子强度
- 付费卡点集（卡一/卡二/卡三）前 1 集必须额外强化悬念密度

## 8. 快速参考卡片

```
【极速模式公式】Hook(3s) → 冲突(15s) → 反转(60s) → 爽点(15s)
【弧光模式公式】开场建置(60s) → 冲突升级(120s) → 高潮反转(60s) → 情感落点(60s)
【字数公式】单集字数 = 时长(秒) x 10~12字
【钩子密度】极速: 10s/钩 | 弧光: 15s/钩 | 长剧集: 每集结尾必留钩
【付费卡点】卡一8-16集 | 卡二25-30集 | 卡三45-55集
【场景上限】单集 <= 3个独立场景
【台词上限】单句 <= 15字
【画幅】9:16竖屏，人物占比 >= 60%
【质量门】7项全Pass方可交付
【特效格式】【特效：…】不计入总字数，三段式：行动段→攻击段→受击段
【特效风格】古武=气浪罡风 | 现代=肌肉打击反馈 | 科幻=机械能量 | 修仙=天地异象 | 异能=场域扭曲
```
