# 剧本 → 全套出图 prompt · 编排流水线(pipeline)

> neoimage-prompt-engine 的**核心编排层**。SKILL.md 解决"一句要求 → 一条 prompt";本文件解决"**一整个剧本/分镜 → 一份生产计划书 + 全套可跑 prompt**"。
> 它是写给执行本 skill 的 AI(你)看的工业流水线工作指令:用户丢来剧本,你按这五个阶段一步步把它变成可生产、可校对的成果,且**每一步都让用户能拦下来核对**。
> 调用的零件:图型骨架在 `shot-types.md`(31 种,四大类),手艺在 `craft-library.md` / `craft-library-2.md`,项目常量在 `project-wenxin.md` / `project-wanwusheng.md`。本文件只做"编排 + 调度 + 引导",不重复零件内容。

---

## 总则 · 这条流水线怎么跑

### 一句话流程
```
剧本/分镜
  → ① 解析:抽四张表(角色 / 场景 / 道具·生物 / 镜头)
  → ② 路由:每个资产·镜头匹配图型(决策树 + tie-break;拿不准先问)
  → ③ 规划:按"资产收敛链"排出生产计划书 ──〔闸1 用户确认计划〕
  → ④ 生成:★全局色卡永远第一张 → 角色定妆 → 镜头;按计划书逐条出 prompt(套图型骨架 + 手艺 + 项目档案)──〔闸2 地基**单图**脸/形态确认 · **闸2a 每个定妆过闸2 后必主动问"要不要转四宫格"**(post-定妆 才决定,严禁在闸1 预先敲死) · 闸2.5 关系板确认才拆单帧〕
  → ⑤ 校对:每条配校对清单,高风险标 MAX + 多种子筛帧 ──〔闸3 成图验收〕
```

### 「AI 自动做」 vs 「必须用户拍板」(贯穿全程,务必分清)
| AI 自动做(做完报告即可) | 必须用户拍板(没点头不往下走) |
|---|---|
| 解析剧本抽四张表 | 表里有歧义/缺失项 → 问用户补,别脑补 |
| 跑分类决策树、写「判定说明」 | 判定**拿不准 / tie-break 仍打平** → 问用户,不硬猜 |
| 排生产计划书草案 | **闸1**:计划书要用户确认才开工 |
| 逐条生成 prompt | **闸2**:地基**单图**(半身锁脸/全身锁形态)出图后,要用户确认"脸/形态对了" |
| 建议要不要补四宫格 + 写清取舍依据 | **闸2a**:每个角色/资产定妆过闸2 后,**必主动问用户"要不要转四宫格 turnaround"**——post-定妆 的独立 opt-in,**不在闸1 预先敲死**(闸1 答"先只做半身"≠ 永久否决,闸2a 仍要再问一次) |
| 写每条的校对清单、标 MAX、建议刷几版 | **闸3**:成图验收由用户拍板;不合格回退重跑 |

### 主动引导铁律(别等用户问"然后呢")
每完成一个阶段或一道闸,**主动告诉用户四件事**:① 现在在哪一步;② 这一步产出了什么;③ 过没过闸/要不要你确认;④ 下一步是什么、需要你做什么决定。
模板:
> 〔现在:阶段③ 生产计划书已出 → 这是 18 条生产项的排序与依赖 → **请过闸1**:确认排序与色卡,我才开工阶段④ → 你需要决定:① 色卡这三个色对不对 ② 陈燃要不要先单独做参考图〕

## 阶段① 解析剧本 ── 抽四张表

> 目标:把自然语言剧本拆成**结构化资产清单**,后续路由/排序全部基于这四张表,不再回头啃原文。
> 这一步 AI 自动做;**唯一要停的地方是"表里出现歧义或缺失"** —— 那就列出来问用户,别替他拍板。

**★ 抽表前先确认一件事:这批图的输出用途?**(它直接决定表D 的颗粒度,见下「首帧切分规则」)
- **视频首帧**(喂即梦/seedance 等)→ 表D 按 **clip** 切(一行=一个连续镜头,连续动作/正反打并入),别按剧本 cut 1:1。
- **逐 cut 分镜板 / 物料 / 提案 hero 图** → 表D 按 cut 或按需精拆。
用途不明**先问用户一句**,别默认——默认错了,整张表D 颗粒度就错,后面全跟着错。

通读剧本,抽出以下四张表。逐镜过一遍,边读边往四张表里填:

### 表A · 角色表
| 字段 | 说明 |
|---|---|
| 角色名 | 剧本里的称呼 |
| 外观锚 | 脸/发/服装一句话(后面做参考图、写身份锚都靠它) |
| 是否已有 ref | 项目档案里有没有现成参考图(查 `project-*.md` 的"角色 ref 清单") |
| 强弱关系 | 谁强谁弱(驱动姿态:强者平静、弱者张扬,见 craft-library 第13节) |
| 固定色 | 该角色/能力锁死的颜色+形态(查项目档案配色铁律) |

### 表B · 场景表
| 字段 | 说明 |
|---|---|
| 场景名 | 地点 |
| 环境一句话 | 废墟/沙漠峡谷/冰墙… |
| 基调 | 跟项目基调走(大逃杀=清爽明亮蓝天;问心=Dune 苍茫),不逐镜重定 |
| 是否需要建场参考图 | 反复出现的环境值得先建一张当背景 ref |
| 是否双人对话场景 → 需关系板(六宫格/图型31) | 该场景在表D 里有 ≥1 段双人(2人)对话/对峙 → 标"需关系板";纯独白/动作/空镜 → 标"否"。**关系板张数 = 标"需"的场景数 —— 解析时就数出来、报给用户,别等生成到一半才发现要补** |

### 表C · 道具·生物表
| 字段 | 说明 |
|---|---|
| 名称 | 武器/载具/机械兽/生物/关键道具 |
| 类型 | 决定走哪种设定图(武器四视图/creature sheet/载具设计图…) |
| 形态命门 | 最易翻车的特征(如赛加"长鼻+螺旋角缺了即失败";地龙"必须读作龙不是虫") |
| 数量/形态锁 | 恰好几个、是否变形(挂形态锁,见 craft-library-2) |

### 表D · 镜头表(核心)
| 字段 | 说明 |
|---|---|
| 镜号 | S1/S2… |
| 谁 | 出场角色(标主次) |
| 在哪 | 引用表B场景 |
| 做什么 | 动作/事件一句话 |
| 景别·机位 | 远景/中景/特写;仰拍/俯拍/平视/荷兰角/航拍 |
| 情绪 | 该镜情绪基调(驱动姿态与打光) |
| 同框人数 | 1人 / 2人 / ≥3人(决定防串脸强度与是否走站位图) |

> ### ★ 首帧切分规则(输出用途 = 视频首帧时,一行 = 一个 clip,别按剧本 cut 数 1:1 立行)
> **表D 一行 = 一个视频 clip = 一段连续镜头**(运镜 + 表演,无硬切),**不是剧本里每一个切镜标记**。落行时套这条:
> - **硬切才立新行**:`[切X]`、景别/机位/被摄主体突变 = 新 clip = 新首帧,立一行。
> - **连续动作/运镜并入,不立行**:同一镜头内的 极缓推 / 缓移 / 转身 / 走位 / 拨灰 / 抬手 / 抬眸 等,能从该 clip 首帧"动起来"的,交给视频生成补,**不另立首帧**。
> - **正反打 fill 镜不写 hero 首帧**:双人对话来回切的反打镜,**直接用阶段2.5 关系板的 6 格当那些 clip 的首帧**;表D 只立"视觉构图真正变化的关键镜"。
> - **量级**:剧本 cut 数 ≥ clip 数 ≥ 要写 hero prompt 的首帧数。**对话戏尤其别按 cut 1:1 出帧**(切得勤但常是同一 blocking 的反打,关系板已覆盖)。
> - 解析完在表D 标一列「并入了哪些连续动作 / 哪些反打走关系板」,让用户一眼看出收敛逻辑。
> ⚠ 仅当输出用途是**视频首帧**时套此规则;若用途是**逐 cut 精拆的分镜板 / 物料**,则回到一 cut 一行。**用途不明先问用户**(见 阶段① 开头·确认输出用途)。

**解析完输出**:四张表给用户看一眼,并主动点出**歧义/缺失**(例:"S7 没写在哪""陈燃没有 ref,要不要先建")。这些**必须用户补**,不脑补。表无歧义即进阶段②。

## 阶段② 分类路由 ── 每个资产·镜头匹配图型

> 目标:把表C的每个资产、表D的每个镜头,各路由到 `shot-types.md` 的 31 种图型之一。
> **每段分派前先甩一行「判定说明」给用户核对**(学 seedance-router);**拿不准先问,不硬跑**。

### 先归大类,再落具体型(四大类速记)
- **Ⅰ 叙事画面(01–09)** = 成片镜头/关键帧:站位图、彩色关键帧、航拍、武戏静帧、特写、微距、重打光。
- **Ⅱ 多格/分镜板(10–13)** = 一张图装多格:九宫格多机位、武戏首尾镜像、状态批量、服装陈列。
- **Ⅲ 工业设定图(14–22)** = turnaround 地基资产:角色四视图、creature sheet、载具/武器/机械兽设计图、比例尺立绘、同物种变体。
- **Ⅳ 物料/平面图(23–30)** = 色卡、灰底抠图、knolling、介绍卡、海报、标题卡、绿幕占位、质感后缀模块。

### 分类决策树(信号 → 图型)
```
这是"资产"还是"镜头"?
├─ 资产(表C/表A里要先建的东西)──────────────── 走 Ⅲ / Ⅳ
│   ├─ 是"角色"且要反复合成下游 → 14 角色四视图定妆
│   ├─ 是"生物/机械兽" → 15 creature sheet(多视图) / 16 侧身正交全景 / 19 机械兽形态图
│   ├─ 是"载具/沙艇" → 18 载具设计图
│   ├─ 是"武器/刀剑" → 20 武器四视图
│   ├─ 要定全片颜色 → 23 色卡 color bible(**这是阶段1项目常量,最先做**)
│   ├─ 要人物与道具比例 → 21 比例尺立绘
│   └─ 同物种不同等级(兽王/精英) → 22 同物种变体
│
└─ 镜头(表D每一镜)──────────────────────────── 走 Ⅰ / Ⅱ
    ├─ 同框 ≥3 人 / 要锁"谁站哪朝向" → 01 上帝视角群像站位图  ★高频
    ├─ 同框 2 人 + 对话戏 / 要锁轴线·视线·正反打覆盖 → 31 正反打双人对话关系板  ★换场景必出(阶段2.5 场景关系锚)
    ├─ 单主角 + 要成片美图/英姿/情绪定帧 → 02 彩色叙事关键帧
    ├─ 大场面/环境交代/高空 → 03 建场航拍
    ├─ 武戏 + 黑白静帧风 → 04 黑白武戏静帧
    ├─ 要脸部/表情/姿态精确复刻 → 06 姿态/表情复刻帧
    ├─ 从已出成图里抠主体特写 → 07 抠主体特写
    ├─ 极近距离质感叙事 → 08 极限微距帧
    ├─ 只想改光、画面不动 → 09 重打光 edit
    ├─ 一个场景多机位想一次性看 → 10 九宫格多机位
    ├─ 武戏动作连续/首尾呼应 → 11 九宫格武戏(首尾镜像)
    └─ 同主体多种状态(完好→被毁) → 12 状态批量九宫格
物料阶段(海报/标题/卡片)→ 26 介绍卡 / 27 EVA 海报 / 28 标题卡 / 24 灰底抠图 / 25 knolling
```

### tie-break 规则(决策树落到两型之间打平时,按序裁决)
1. **"要不要当下游参考图"优先**:若这张图后面要被别的镜头当 ref 喂进去,一律走 Ⅲ 设定图(多视图/正交),哪怕它看着也能当关键帧。地基性 > 美观性。
2. **人数定生死**:≥3 人且要读站位 → 永远 01(站位图,影调正确优先),不要因为"想要美"滑去 02。01 与 02 是一对反义图型(01 多人/影调正确优先,02 单人/美感优先)。**2 人对话戏 + 要锁轴线/视线 → 31 正反打关系板**(平视),与 01(俯视站位)是"关系交代"的平视/俯视一对;31 是该场对话所有 02 单帧的轴线/视线真源,先出 31 再拆 02。
3. **"建大特效" vs "改单点"**:涉及从无到有的大特效/大场面 → Ⅰ 叙事建场(Image 2 重型);只动一处(光/颜色/姿态单点)→ 09 重打光 或 Nano Pro 改图。
4. **多格 vs 单帧**:用户要"一次看多个角度/机位/状态"才进 Ⅱ 九宫格;否则一镜一图。⚠ 数量是 Neo Image 2 弱项,九宫格只适合"同主体多视图",不适合"多个不同镜头"(见 craft-library 第12节)。
5. **仍打平 → 不裁,问用户**。

### 拿不准就问,不硬跑(铁律)
出现以下任一,**停下问用户**,别选一个硬跑:
- 决策树两个分支都说得通,tie-break 走完仍打平;
- 镜头描述模糊到读不出景别/人数/谁是主体;
- 资产形态命门不清楚(如"机械兽长什么样"剧本没写全);
- 混合性质(既是设定图又像关键帧)。

### 混合剧本先拆段再逐段分派
若一段剧本既有"建资产"又有"出镜头"、或既有文戏镜头又有奇观镜头,**先把它拆成独立单元,再逐单元跑决策树**,各出各的判定说明。不要一锅烩。

### 「判定说明」输出格式(每个资产/镜头一行,给用户核对)
```
〔<资产/镜号> → <图型号 图型名(中文)> · <Ⅰ/Ⅱ/Ⅲ/Ⅳ 大类> · <重型建 Image2 / 轻改 NanoPro> · <参考图依赖:用到哪些上游资产>〕
```
示例:
> 〔林雪(角色) → 14 角色四视图定妆 · Ⅲ设定图 · 重型建 · 无依赖(地基资产)〕
> 〔S6 林雪过肩立冰墙(单人英姿) → 02 彩色叙事关键帧 · Ⅰ叙事 · 重型建 · 依赖[林雪四视图]〕
> 〔S12 三人废墟对峙 → 01 上帝视角群像站位图 · Ⅰ叙事 · 重型建 · 依赖[风刃男ref + 林雪四视图 + 废墟背景ref + 色卡]〕

全部判定说明列完 → 进阶段③。**注意每条都标了"参考图依赖",这是阶段③排序的输入。**

## 阶段③ 规划排序 ── 按"资产收敛链"排出生产计划书

> 目标:把阶段②那一堆"带依赖"的生产项,排成一份**有先后、有依赖、可勾选**的生产计划书。
> 核心原理 = **资产收敛链**(craft-library-2 第3节):下游图靠上游图当参考图收敛,**上游没做好,下游必崩**。所以顺序不是建议,是硬依赖。

### 五个生产阶段(严格按此顺序,理由见下)

**阶段1 · 项目常量(全片地基,最先锁)**
- 色卡 color bible(图型23)、形态锁清单、题材级负词库。
- **★ 铁律:全局色卡永远是第一张交付物 —— 任何角色定妆 / 镜头之前先出色卡。** 色卡两件套:① **文字 HEX 真值**(写进每条 prompt 的 [特效层]/【锁定】/【Avoid】,这才是颜色真源)② **可视化色卡板**(图型23,给人眼检整体配色协调)。⚠ 板上渲染的 HEX 小字不可靠、会糊(craft-lib-2 §10),**真值以文字码为准,别从板上回读**;板只核"色相分布 / 分组对不对"。
- **来源(reference-driven · SKILL 总纲第一律)**:色卡是图生图产出 —— **用户给一张电影感场景剧照 → 图型23 从那张剧照提取主/辅/点缀调色板生成色卡**;产出的色卡既是 HEX 真源,又作为"电影感色调"参考图喂进后续每条 prompt。基调可从 `project-*.md` 继承(大逃杀=清爽蓝天调;问心=Dune 调),但**颜色真值来自用户那张场景剧照的提取**。没有电影感场景图 → 先问用户要,不凭空定色。
- **为什么最先**:色卡/形态/负词是后面每一条 prompt 都要嵌进去的常量。没锁死色卡就出图,各镜颜色必漂(同一硬色要在[特效层]+【锁定】+【Avoid】三处各写一遍,见 craft-library 第4节)。

**阶段2 · 地基资产(下游的"参考图原料")—— ★ 两步走,别一上来就出四宫格**
角色 / 怪物这类资产**一律分两步生成**(对"生成所有角色或怪物"通用):
- **第1步 · 地基单图(按命门二选一取景,焊死最难那项)**:
  - **真人/写实脸角色(脸一致性是命门)→ 半身锁脸优先**:先出一张**半身像(腰以上,竖幅 2:3)**,图生图锚定用户参考图,**最好带场景背景**(暖阁/废墟等虚化在身后,让定妆已落在世界里)。**为什么半身**:面部在画面占比大、像素多,五官/身份能完全控制住,串脸/漂脸风险最低——脸是真人角色最难的一致性命门,先用半身把它焊死。
  - **形态命门类资产(怪物/机械兽/载具)→ 全身/正交优先**:先出单张全身亮相(竖幅 2:3 / 9:16 取全身最稳),把形态/比例/配色刷对。
  这一张就是下一步四宫格的脸(或形态)/ 配色真源。
- **第2步 · 四宫格 turnaround(必须先问用户要不要,不自动转)**:用户确认要,才把**第1步那张图当参考图 Image 1 喂进去**,二次(Edit / 图生图)转成多视图四宫格设定 sheet —— 角色走 图型14(house 四宫格:左上正脸 / 右上侧脸 / 左下正面身 / 右下背面身 · 摄影棚定妆 · 单侧暖光侧逆光;**脸继承第1步半身**,四宫格补全身正/背/侧),生物 / 怪物走 图型15(盲掘巨足类 v4 格式:四视图 + 人形比例尺 + 五物种比例条 + hex 色板条)。武器/载具/机械兽(18/19/20)、比例尺(21)同理:先全身亮相,再(询问)转设定图。
- **为什么这么分**:① 一上来就让模型出四宫格,脸/形态还没定就被摊成 4 格,常 4 格都不一致;先出一张地基单图(半身锁脸 / 全身锁形态)把身份/形态焊死,再拿它当 ref 转四宫格,4 格才同一个。② 很多镜头其实只要那张地基单图当 ref 就够(半身锁了脸,贴近镜头的对话/特写帧直接够用),四宫格是"要侧/背/全身视角才追加"的可选项 —— 别默认全做。
- **为什么必须在镜头之前**:阶段3 的群戏/关键帧是"图生图",要把这些资产当参考图喂进去锁脸/锁形态。**没先有角色/怪物的稳定参考(地基单图,必要时再四宫格)就去合成群戏 → 模型凭文字脑补脸 → 必串脸、必崩**。
- **闸2 拆成 闸2 → 闸2a → 四宫格确认 三段,严禁合并跳步**:〔**闸2** 地基单图确认(半身锁脸 / 全身锁形态)〕→〔**闸2a** 单图过闸后**必主动问用户"要不要转四宫格"**;turnaround 是 post-定妆 才能判的可选项(下游要侧/背/全身视角才追加),**这个取舍只在此刻问,不前置到闸1 计划阶段一次性敲死**——闸1 只排关键帧范围,**用户在闸1 说"先只做半身"也不算永久否决,闸2a 仍要在锁脸后再问一次**〕→ 用户要 → 转四宫格 →〔四宫格脸一致确认〕;过了才解锁下游。

**阶段2.5 · 场景关系锚(对话戏专用 · 一个对话场景一张,数量在规划期就定)**
- **★ 关系锚是「01 俯视站位 + 31 平视正反打」一对,01 先出(给全身 + 远景关系参考)**:
  - **图型01 上帝视角站位图(俯视)**= 鸟瞰交代"谁站哪、谁离谁多远、各自全身姿态",**双人全身可见**。它不只是 ≥3 人才用——**2 人对话场景同样值得先出一张**,因为它给下游提供两样关系板没有的东西:① **双人全身**(关系板只给上半身/脸);② **空间关系远景**(下游的中景/全身/走位帧 K 拿它当 blocking 参考)。
  - **图型31 正反打关系板(平视)**= 锁 180°轴线 + 视线 + 正反打覆盖(脸/上半身)。
  - **顺序:01 先,31 后**(俯视定空间站位 → 平视定轴线视线);两张的左右站位/朝向必须**互相一致**(虞晚左/谢凛右,两图同)。
  - 2 人场景的 01 是 **opt-in**(下游有全身/走位/远景帧就推荐做;纯贴脸特写对话可只做 31),和关系板一样规划期问用户。
  - **★ 01 不只是参考,是 blocking 真源——必须当 Image 喂回下游 + 按它推翻脑补**:01 跑出来后,**所有该场景的双人帧 / 全身帧 prompt 必须把 P2.4 作为参考图喂进去**,并按 01 实拍的真实 blocking **重写**之前凭空脑补的"谁在哪、谁高谁低、距离多远、谁俯谁仰"。常翻车点:作者写 prompt 时凭剧本字面想象 blocking(如"越肩贴身"),01 一出来才发现真实空间是"隔屋对峙、一人在高榻一人在地面、中间隔香炉"——此时**整张 prompt 的体位/相对高度/距离/视线方向都要按 01 重写**,不要拿脑补的 prompt 硬跑(必崩)。01 的回灌方式:① 列为该帧的 Image N,标注"blocking truth source — strictly follow positions/heights/distance/orientation";② 在 CONSTRAINTS 段把 01 读出来的 4 项硬指标(位置/相对高度/距离含中间隔物/视线方向)逐项写死;③ Avoid 段把"脑补 blocking"(如"越肩贴身/齐高站立/俯仰反了")写成负向铁律。
  - **★ P2.4 管的是 blocking,不是 cinematography——剧本指定的机位/景别不许被 P2.4 推翻**:**P2.4 真源 4 项硬指标 = ① 位置(谁在画面左/右)② 体位(谁坐/卧/倚/立)③ 相对高度(谁高谁低、谁俯谁仰)④ 朝向(谁面向谁/视线方向)**。**它不改 ⑤ 机位/景别(越肩 / 中景 / 特写 / 大特写 / 仰拍 / 俯拍 / 远景)——这是剧本 cinematography,P2.4 无权改写**。踩坑实例:剧本 S3 明写 `[越肩构图|虞晚虚化前景]`,我按 P2.4 真源(她卧低榻、谢凛立屏风)**擅自把越肩改成 wide shot across the room**,结果机位错了。正确做法:**机位照剧本(还是越肩)、体位/俯仰按 P2.4 校(虞晚作前景越肩元素时是卧姿的肩——在画面左下而非左上;谢凛立、所以俯视她)**。同理:剧本写"大特写",P2.4 显示两人隔屋,**大特写仍是大特写**(只拍一人脸),P2.4 影响的是"被拍那一人的体位 + 视线方向",不是"改成 wide"。**简记**:**P2.4 改人物在画面里"如何摆",不改"镜头放哪、拍多大"**。机位/景别永远以剧本/分镜表为准。
  - **★ 01 多版必须钦点一张作 final truth source,且全程冻结;换版要回头校全部下游**:同一场景刷 6–8 版 01 时,**不同种子之间 blocking 会变**(实测:同剧本同 prompt,版本A 是"她在带阶高榻、她俯他仰",版本B 是"她在低 chaise、他俯她仰",**仰俯方向直接相反**)。所以:① 用户从多版里**钦点一张作 final**(必须用户拍板,不替选);② 钦点后**冻结 P2.4 final**,所有下游 prompt 都基于这一张写,**不要在前一张 prompt 上小改**(旧 blocking 必残留);③ 若中途换 final(如发现更好的一版),**所有已写的下游 prompt 必须回头按新 final 重新校 4 项硬指标**(位置/相对高度/距离/视线方向),不是只校"刚开始写的那张"。**fire-and-forget 是踩坑模式**:踩过的实例—— K2 v2 按上一版 P2.4 写完(她高他俯),新版 P2.4 一出俯仰就反了(他高她仰),整张 prompt 推翻重写。机制:**P2.4 final 是冻结基线,变了就触发下游全员重校**。
  - **★ P2.4 信号常被角色 ref 的近景特征盖过,要显式提权 + 给其他 Image 降权**:实战 failure—— 下游帧喂了 4 个 Image(角色A 定妆 + 角色B 定妆 + P2.4 + 场景),但出图是越肩近景、丢了 P2.4 的"隔屋 + 中间隔物"远距离 blocking。根因:**角色 ref(尤其半身定妆)自带"特写/近距离"语义信号**,模型倾向把它们当近景前景参考用,把 P2.4 远景 blocking 当背景细节忽略了。**3 步加固**:① **正文开头一行**显式钉 P2.4 优先级:`★ THIS IS A WIDE MEDIUM SHOT ACROSS THE ROOM, NOT close-up / NOT over-the-shoulder. Strictly follow Image N (P2.4) ABOVE ALL OTHER REFERENCES — its blocking supersedes any closeness implied by the character refs ★`;② 每张角色 ref 标注改成 **`identity ONLY, NOT a closeness / framing reference`**,把它从近景参考里降权,显式说该角色在画面里**是远是近**(`appears in the FAR background, NOT as a near foreground`);③ Avoid 段把可能滑去的近景框架族**逐项排除**:`over-the-shoulder framing / shoulder-to-shoulder closeness / near two-shot / close-up of both faces / character X as a near foreground filling the edge / the table and incense burner missing or cut out of frame`。这套加固覆盖"01 真源被角色 ref 盖过"的 failure mode,适用所有 P2.4 喂下游的双人帧。
- **★ 首次规划就数出张数 + 让用户 opt-in**:解析完(表B 标"需关系板"的场景)即可算出**关系板总张数 = 双人对话场景数**。开工前**主动报给用户并确认**:〔本剧本有 N 个双人对话场景(场景X / Y…)→ 需 N 张关系板(六宫格)→ 全部生成?还是只做哪几个场景?〕——和四宫格(闸2a)一样是 opt-in,不替用户默认全做或全不做。
- **★ 场景切换硬护栏(多场景剧本必守)**:生产推进时**每进入一个新的对话场景(表D 的"在哪"换到新的表B 场景行),必须先回本阶段出该场景自己的关系板、过闸2.5,才拆该场景的关键帧**。**绝不跨场景套用上一场的轴线板**——每个场景的 blocking / 左右站位 / 视线方向都不同,套错就整场跨轴。漏出一张 = 那个场景所有对话帧失去轴线真源。
- **双人对话场景在拆单帧前,先出一张 图型31 正反打关系板**,锁死该场景的 180°轴线 + 视线方向 + 正反打覆盖(过肩对 / 近景对 / 中近对 共 6 格)。
- 它是该场景所有对话关键帧的**轴线/视线真源**:阶段3 的该场景 02 单帧全部继承这张板的左右关系(A 恒左 / B 恒右、视线方向恒定),后期单独抽帧不跨轴、视线不漂——这正是"成套出图有利于后期单独分镜"的来源。
- **过一道轻闸(闸2.5)**:确认轴线/视线对、6 格脸一致,再放行该场景的阶段3 关键帧。它是 blocking 级(位置/朝向/轴线优先于美感),**建议多种子刷 6–8 版**挑最齐那张。
- **为什么在地基之后、关键帧之前**:它要把阶段2 的角色定妆当参考图喂进去锁脸;它本身又是阶段3 该场对话帧的参考图。**只对"有对话/双人对峙的场景"做;纯独白/动作/空镜场景跳过此层。**

**阶段3 · 关键帧 / 站位图(用阶段2资产合成的成片镜头)**
- 群像站位图(01)、彩色关键帧(02)、航拍(03)、武戏静帧(04)、复刻帧(06)、九宫格分镜(10/11/12)。
- 每条的参考图 = 阶段1色卡 + 阶段2对应设定图 + 必要的环境 ref。**这一阶段才是"出分镜图"的主体产能**。
- **为什么在地基之后**:同上,它消费地基资产。地基没过闸2,这里不开工。

**阶段4 · 物料 / 海报(基于成片帧或资产做平面)**
- 介绍卡(26)、EVA 海报(27)、标题卡(28)、灰底抠图(24)、knolling(25)。
- **为什么在后**:海报常要抠用阶段3出好的成片帧或阶段2的设定图,是下游的下游。

**阶段5 · 轻型修(Nano Pro 单点微调)**
- 改颜色/改高度/治糊升清/局部修(走 Nano Pro 中文一句话,见 SKILL 第二节双寄存器)。
- **为什么最后**:修的是前面已出的图,本质是收尾打磨,不产生新资产。

### "为什么顺序不能错"一句话总结
> **色卡(常量) → 设定图(原料) → 关系板(对话戏锁轴线/视线) → 关键帧(用原料合成) → 物料(抠成品) → 修(打磨成品)**。每一层都消费上一层的产物当参考图。跳级 = 让模型凭空脑补它本该从参考图读取的东西 = 串脸/漂色/形态崩/跨轴。**资产收敛链是单向的,不能倒着跑。**

## 阶段④ 逐步生成 ── 按计划书逐条出 prompt

> 目标:照生产计划书**从 P1 往后逐条**生成可直接跑的 prompt。每条都是"图型骨架 + 手艺 + 项目档案"三件套填出来的。
> 这一步 AI 自动做(逐条出 prompt);**但地基资产(阶段2)出图后要过闸2才能往阶段3走**。

### 每条 prompt 的生成动作(固定四步)
1. **取图型骨架**:按该项的图型号,去 `shot-types.md` 取对应"专门骨架(填空)",直接照填(站位图填 depth-order、关键帧填"参考图管脸/prompt管构图"、四视图填 turnaround 结构…)。
2. **套手艺**:把相关手艺嵌进去 —— 六段式/双寄存器/防串脸三件套/颜色三处复写/高度用构图关系/质感正负词库(`craft-library.md`);重型 prompt 的 API 参数段/HEX 色板/CONSTRAINTS 三句式/形态锁(`craft-library-2.md`)。
3. **灌项目档案**:把阶段1锁的色卡、形态锁、角色身份锚、题材负词,从 `project-*.md` 填进对应段([特效层]颜色 / 【锁定】身份+形态 / 【Avoid】负词)。
4. **标依赖与操作**:写清这条**传哪几张参考图**(就是计划书里的"依赖"项)、size/quality、清晰度、是否开 Thinking Mode、建用 Image2 还是改用 Nano Pro。

### 出 prompt 的顺序纪律
- 严格按计划书 P1 → P2 → P3 → P4 → P5。
- **阶段1常量先出**(色卡 prompt),它本身也是一张要跑的图,且是后面所有 prompt 的颜色来源。
- 到**阶段2每个地基资产**:出完它的 prompt + 校对清单(阶段⑤),然后**停下过闸2**,不要继续往阶段3堆。
- 阶段3及之后:每条 prompt 的"参考图依赖"必须指向**已过闸的**上游资产;若依赖项还没过闸2,这条不能出(会出现"参考图还不存在"的空依赖)。

### ★ 闸2 · 地基资产确认(没过不下游合成)
阶段2每个关键地基资产(角色四视图/creature sheet/武器设定图等)出图后,**主动请用户过闸2**:
> 〔P2-1 林雪 半身定妆已出 prompt + 校对清单 → 请你**跑图并过闸2**:确认 ① 脸锁住了 ② 形态/服装对 ③ 颜色合色卡。〕

### ★ 闸2a · 四宫格取舍(每个定妆过闸2 后必问 · 别跳)
**地基单图过闸2 后,无论用户在闸1 怎么说过范围,都必须主动再问一次**:
> 〔P2-1 林雪 半身定妆已过闸2、脸锁住了 → **要不要把它转成四宫格 turnaround(补正脸/侧脸/全身正/背视角)?** 很多贴脸的对话/特写帧只用这张半身当 ref 就够,四宫格是"下游要全身/侧背视角才追加"的可选项。要 → 我出 图型14 prompt 并过〔四宫格脸一致确认〕;不要 → 直接进阶段3 关键帧。〕

**为什么必问、不能省**:turnaround 是 post-定妆 才判得清的可选项,只有锁脸后才知道下游镜头要不要侧/背/全身视角。**闸1 是关键帧范围规划,不是 turnaround 的最终裁决**——用户在闸1 说"先只做半身"是当时无图状态下的默认,**不等于永久否决**;锁脸后(闸2a)必须把这个 opt-in 重新摆到用户面前。漏掉这一问 = 把计划阶段的临时答案冒充成最终决定。

地基资产没过闸2 → 依赖它的阶段3镜头**一律不开工**。这是防止"拿一张串脸的图去合成群戏、把错误放大到每一镜"的关键闸。

## 阶段⑤ 校对 ── 每条配校对清单 + 高风险 MAX + 多种子筛帧

> 目标:每条 prompt 出图后,给用户一份**该图型专属的校对清单**逐项对账;把高风险特征标 MAX,建议刷几版多种子筛帧。
> 这一步产出"怎么验"的标准;**验收本身由用户拍板(闸3)**。

### 每条配校对清单(直接取自图型条目)
`shot-types.md` 每个图型条目都自带"校对清单",生成 prompt 时**一并把该图型的校对清单附上**。例:
- 站位图(01):depth order 几层都读出来了?巨物够大当分割墙没?有没有串脸?长投影出来没?机位是真高空斜俯吗?
- 彩色关键帧(02):脸是参考图锁的没被 prompt 描述串脸?视觉锚点唯一吗?冷暖对撞出来没?着装没被脑补成战斗装?
- 四视图(14)等设定图:四视角脸一致?形态命门(赛加长鼻+螺旋角/地龙读作龙)在不在?合色卡?

### 高风险特征标 MAX
把**已知最易翻车**的特征显式标 `⚠ MAX`,提示用户重点盯 + 多刷:
- 多角色同框 → **串脸 MAX**(防串脸三件套照打,Avoid 写 faces swapped or merged)。
- 形态命门资产 → 如问心赛加"长鼻+螺旋角缺即失败"、地龙"必须读作龙不是虫"、江流"非人类黑屏脸" → **形态 MAX**。
- 数量类(九宫格/多个目标)→ **数量 MAX**(Neo Image 2 弱项,必靠多跑筛)。
- 颜色对垒镜 → **漂色 MAX**(双区分轴 + 三处复写)。

### 多种子筛帧建议
对高风险/复杂调度的图(尤其站位图01、九宫格、形态命门资产),**明确建议用户冻结 prompt + 连刷多版多种子挑最准那张**——这是标准产能方式,不是写完跑一次就收(站位图 gid95–113 同 prompt 连刷约8批挑命中)。给出建议刷版数(如"群戏站位建议刷 6–8 版")。

### ★ 闸3 · 成图验收(用户拍板)
每条图出来后,**主动请用户过闸3**:
> 〔P3-2 三人对峙已出图 → 请你**对照校对清单验收(闸3)**:逐项打勾;⚠MAX 项(串脸/巨物尺度)重点看。合格 → 这条收,进下一条;不合格 → 告诉我哪项崩,我判断是"改单点(回阶段⑤轻修/Nano Pro)"还是"换姿态级大改(回阶段④ Image2 重起)"。〕

不合格的回退规则:
- **单点崩(光/颜色/局部)** → 走阶段5轻型修(Nano Pro 一句话改,其余不变)。
- **换姿态/换机位级大改** → 回阶段④用 Image2 重起这条(Nano 拽不动,别在微调里硬磨,见 SKILL 第二节)。
- **地基资产崩** → 回阶段2重刷该资产并重新过闸2,**所有依赖它的下游镜头一并回炉**(因为它们都引用了错的参考图)。

## 收尾

全部生产项过闸3后,主动给用户一份**完成清单**:出了哪些图、各对应镜号/资产、哪些刷了多版、还剩哪些待修。并更新生产计划书的勾选状态,告知"全片出图 prompt 已交付,需要新增镜头/改某条随时回到对应阶段"。
