## 1. 状态与恢复

内部状态至少包含：

```text
项目标识
工作配置：adaptive｜exact_25_30_8｜extended
剧本与故事合同版本
单元表、镜头表、片段表版本与状态
各片段站位、可选故事板、视频Prompt版本与状态
时间线校验方式与最近结果
```

状态只使用：`草稿｜自检中｜待用户确认｜可用｜已失效｜硬阻塞`。

不要假定内部思考或隐藏台账能跨会话永久保存：

- 同一对话继续时，从最后一次用户可见的已确认片段表和后续交付恢复。
- 上下文不完整时，重新读取用户提供的剧本和最后确认版本，不凭记忆补全。
- 只有用户明确要求跨会话项目状态时，才把状态写入工作区文件；不得写入安装目录。
- 旧版本可用于追溯，但不得继续驱动生成。

## 2. 故事合同与台账

从原剧本锁定：

- 人物、群体、数量、关系和出场顺序；
- 场景、时间、天气和空间关系；
- 动作、事件、能力规则和因果顺序；
- 关键道具归属、交接和最终状态；
- 对白、OS、通信画外对白和声音需求；
- 用户明确要求保持或排除的内容；
- 故事结果。

内部建立：

```text
必需实体台账：实体｜类别｜剧情职责｜出现片段｜状态
对白台账：ID｜说话人｜对象｜原文｜声音类型｜原镜号｜片段｜最终镜头
连续性台账：片段｜人物位置与状态｜道具归属｜环境变化｜运动方向｜声音状态
```

不得把外观推测升级为身份、年龄、关系、职业、性格或剧情事实。

## 3. 信息权威

冲突时按以下顺序处理：

1. 原剧本决定剧情事实、人物关系、事件因果、对白、OS和结果。
2. 通过审校的八列镜头表决定景别、机位、动作、声音和特效底稿。
3. 用户已确认的片段表决定片段边界、实际时长、镜头范围和剪辑连接。
4. 通过审校的人物站位决定左右、前后、朝向、距离、视线、路径和场景锚点。
5. 可选故事板只校准复杂构图与动作阶段，不改写剧情。
6. Prompt编译规则只决定提交文本的组织方式。

当下游与上游冲突时，回退到最早受影响阶段修正。

## 4. 自动审校闭环

每个阶段执行：

```text
生成草稿
→ A轮：故事忠实度与完整性
→ 最小修正
→ B轮：时间、生成可行性与连续性
→ 最小修正
→ 确定性时间线校验（可运行脚本时）
→ 全量复查
```

A轮检查人物、事件、能力、对白、道具和结果没有新增、遗漏或改写；每个有效节拍和每句对白都有唯一归属。

B轮检查：

- 镜号、起止时间、时长和全片覆盖连续；
- 内容可见、可拍、可生成，特效用白话且无特效写`无`；
- 动作、问答、运镜和特效因果不被切断；
- 人物左右、朝向、视线、移动方向、持物手和道具归属连续；
- 片段符合当前工作配置；自适应配置中的偏离有真实理由；
- 严格配置已经通过时长、自然切点、对白容量和有效镜数检查；
- 最终Prompt台词唯一、口型正确、参数分离且没有虚构引用。

时间线脚本返回的`error`必须修复。`warning`只允许用于自适应配置的偏好偏离或非致命提醒，并须在片段表说明。无法运行脚本时明确记录`人工规则检查`，不得伪造脚本结果。

## 5. 外部参考素材

人物、场景、动物、道具、武器和载具参考由用户在生成端挂载。

默认：

- 不索取、不因缺图暂停；
- 不编号、排序、猜测身份或建立映射；
- 不根据上传顺序推断主体；
- 不把未提供标签写入Prompt；
- 不检查平台图片数量上限。

最终Prompt默认只写：

```text
人物与场景的视觉身份以生成端已挂载的参考素材为准。
```

用户主动提供精确标签和职责时，例如`@图片1＝苏晚，@图片2＝客厅`，才按原文引用。不得改号、补号、猜测或扩展职责。

## 6. 版本失效

| 修改内容 | 最早回退点 | 同时失效 |
|---|---|---|
| 剧情事实、人物、能力、动作链、对白、出场顺序 | 镜头表 | 旧时长、片段、站位、故事板、Prompt |
| 工作配置或生成端时长能力 | 片段可行性检查 | 片段、站位、故事板、Prompt |
| 镜头时长、顺序、景别或运镜 | 镜头表 | 片段、站位、故事板、Prompt |
| 片段边界或剪辑连接 | 片段表 | 对应站位、故事板、Prompt |
| 人物方位、视线、路径或道具位置 | 人物站位 | 对应故事板、Prompt |
| 可选故事板构图或动作校准 | 人物站位 | 对应Prompt |
| 只修改最终Prompt措辞 | 视频Prompt | 不使上游失效 |
| 用户在生成端更换参考图 | 不回退 | 由用户负责挂载一致性 |

用户确认前，镜头表与片段表标为`待用户确认`；确认后标为`可用`。单项Prompt审校不把缺失的上游阶段虚构为`可用`。
