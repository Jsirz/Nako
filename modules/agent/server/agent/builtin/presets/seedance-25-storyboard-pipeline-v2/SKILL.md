# Seedance 2.5 剧本视频流水线（自适应版）

## 目标与边界

把成形剧本转成可审阅、可校验、可继续生成的视觉生产包：

`输入识别 → 单元与镜头表 → 全片统一切片 → 确定性校验 → 用户确认 → 人物站位 → 可选故事板 → 视频 Prompt`

区分两类规则：

- **平台能力**：由用户实际使用的生成端决定；标准生成通常不超过30秒，扩展模式只在用户明确启用且当前生成端支持时使用。
- **制作配置**：25–30秒与8镜是本 Skill 的默认偏好，不冒充模型硬限制。

始终优先保护原剧本事实、完整对白、动作因果、主要角色视觉入场和自然剪辑点。不得为了时长或镜数擅自新增剧情、台词、人物、道具或结果。

## 工作配置

### 默认：自适应制作配置

- 每段必须在当前生成端允许的时长范围内；标准模式按5–30秒处理。
- 优先组织为25–30秒、目标8个有效镜头。
- 无法同时满足偏好与剧情完整性时，允许较短片段或非8镜片段；镜数由真实视觉节拍决定，不用微动作凑镜。
- 在片段表的`规格状态`中写明`命中偏好`或偏离原因，不把正常降级写成错误。

### 可选：严格制作配置

只有用户明确要求“每段必须25–30秒且恰好8镜”或同义要求时启用。

切片前先做必要可行性检查：若自然总时长为`T`、片段数为`n`，至少应存在整数`n`满足`25n ≤ T ≤ 30n`；同时每个不可拆对白或动作单元必须能装入30秒，每个片段必须能从原有有效节拍合法组织出8镜。该条件只是必要条件，仍须检查自然切点和内容容量。

若严格配置无法在不破坏原作的前提下成立，将其视为硬阻塞，一次询问用户选择：改用自适应配置、修改内容，或改用当前生成端支持的扩展方案。不得静默拉长、压缩或伪造“自检通过”。

### 可选：扩展时长配置

只有用户明确要求且当前生成端已确认支持扩展时长时启用。先核实该端实际可选范围，再按同一套动作、对白、镜头和连续性规则切片；不得仅凭模型名称假定180秒模式可用。

## 运行模式与确认门

### 完整流水线

默认只设一个用户确认门：输出单元表、镜头表与片段表并通过校验后暂停；用户确认片段边界后再生成站位和最终 Prompt。用户明确说“直接全部完成”时可以跳过确认门。

### 单项审校

- 只有现成 Prompt：直接按 Prompt 编译规则审校，不要求补造上游确认；明确这是`单项审校`，不声称镜头表和片段表已经完整验证。
- 已有站位文字但没有已确认片段表：先重建或核对片段与镜头范围，输出片段表等待确认。
- 已有且用户明确确认的片段表：从站位阶段继续。
- 已有故事板：只提取可靠的空间校准结果；没有已确认片段表时仍须先补齐片段确认。

不要重复可靠的现有工作。

## 允许暂停的硬阻塞

仅在以下情况合并为一个简短问题暂停：

- 原剧本存在会改变人物身份、事件因果、关键道具归属或结局的直接矛盾；
- 标准模式下，单句不可拆原文对白按合理语速仍超过30秒；
- 两种处理会产生不同剧情事实或人物关系，无法用最小改动原则决定；
- 核心剧本文本不可读取或缺失；
- 用户启用严格制作配置，但时长、镜数、对白或动作容量检查证明无合法解。

参考图缺失、未编号、不可读或未映射不是硬阻塞。

## 阶段零：输入、权威与项目状态

首次处理项目或上游变化时，完整读取 [references/project-state-and-assets.md](references/project-state-and-assets.md)。

1. TXT、Markdown和粘贴文本直接读取。DOCX 使用当前环境可用的文档读取能力完整提取正文；无法可靠读取核心文本时才暂停。
2. 原剧本决定剧情事实、人物关系、对白、OS、通信画外对白、事件因果和结果。
3. 通过审校的镜头表决定镜头结构；已确认片段表决定边界；站位文字决定空间；故事板只做校准；编译规则只决定 Prompt 组织方式。
4. 参考素材由用户在生成端挂载。默认不索取、不编号、不猜测、不映射；只有用户主动提供精确`@图片N`或`@Image N`标签和职责时才原样使用。
5. 不假定隐藏状态能跨会话永久保存。每次继续任务时，从用户最后确认的可见表格重建状态；只有用户要求跨会话项目文件时才写入状态文件。
6. 用户修改剧情、动作链、对白、镜头要求或角色出场顺序后，使受影响的镜头时长、片段边界和下游结果失效，并从最早受影响阶段重算。

## 阶段一：单元与镜头表

完整读取 [references/shot-and-segment-25.md](references/shot-and-segment-25.md)。

1. 通读剧本，建立故事合同、必需实体、对白台账和连续性台账。
2. 输出七列单元结构表。
3. 按单元输出八列镜头表：`镜号｜时间｜时长｜景别｜机位·运动｜内容｜声音｜特效`；全片镜号和时间连续。
4. 先按真实节拍拆出自然镜头，不提前为了8镜改变镜头结构。
5. 内容只写可见、可拍、可生成的动作、过程、结果和连续性细节；特效用白话，没有则写`无`。
6. 自动检查镜号、时间、动作、声音、左右、视线、运动方向和道具归属；失败时最小修正后全量复查。

## 阶段二：全片统一切片与校验

继续使用 [references/shot-and-segment-25.md](references/shot-and-segment-25.md)。

1. 先查看整条镜头时间线和自然切点，再统一划分；不从前往后机械凑秒数。
2. 不切断动作因果、句中对白、完整问答、快速运镜或主要角色首次视觉入场。
3. 按当前工作配置处理时长和镜数。默认优先25–30秒、目标8镜；严格配置必须先通过可行性检查。
4. 为相邻片段写清`上一段出点 → 剪辑方式 → 下一段新入点`，不复制上一段末镜。
5. 在输出前建立时间线 JSON 台账，并使用当前环境可用的 Python 3 解释器运行：

   `python scripts/validate_timeline.py <timeline.json>`

   如果`python`不在PATH中，先查找当前运行环境提供的Python可执行路径；在Codex Desktop中调用`codex_app__load_workspace_dependencies`（界面可能显示为“加载工作区依赖”）并使用其返回的Python路径。只有确认环境没有Python解释器，或用户明确禁止创建临时台账文件时，才退回人工检查；不要因PATH缺项直接跳过脚本。

   修复所有 error；warning 可以保留，但必须在片段表中说明对应偏离原因。若环境无法运行脚本，执行同等人工检查并明确写`校验方式：人工规则检查`，不得声称已执行脚本。
6. 输出单元表、完整镜头表和片段表后等待用户确认；全自动模式除外。

## 阶段三：人物站位与可选故事板

片段已确认或用户启用全自动模式后，完整读取 [references/spatial-blocking-25.md](references/spatial-blocking-25.md)。

1. 为每段输出`【人物站位】`；有明显位移时增加`【动作路径】`，终态不清时增加`【结束状态】`。
2. 校验左右、轴线、视线、距离、路径、门窗、道具和相邻片段连续性。
3. 普通文戏和空间明确的动作只用文字站位。
4. 复杂打斗、多人交叉走位、镜面/反射、瞬移/换位或跨空间运动时，读取 [references/storyboard-generation-25.md](references/storyboard-generation-25.md)。默认先做文字节拍校准；只有用户明确要求生成故事板图片或明确启用自动故事板时，才调用图片生成。
5. 调用图片工具前用一句话告知用户。图片工具只返回图像而没有本地路径时，直接检查返回图像，不虚构保存路径。

## 阶段四：编译或审校视频 Prompt

完整流水线进入本阶段时，读取 [references/seedance-25-prompt.md](references/seedance-25-prompt.md)。当前片段以人物关系和情绪表演为主时，再读取 [references/emotional-drama-30s.md](references/emotional-drama-30s.md)。

1. 每个已确认片段独立输出一条 Prompt；单项审校则只忠实优化用户提供的 Prompt。
2. 镜头编号使用`镜头1`至`镜头N`，`N`必须等于已确认片段的实际镜头数；严格8镜配置下才硬性要求`N=8`。
3. 每句对白、OS和通信画外对白原文出现一次且只出现一次。
4. 默认加入：`人物与场景的视觉身份以生成端已挂载的参考素材为准。`
5. 最终正文从`【分镜】`开始，按`【分镜】→角色声线→【禁止项】→【强制声明】`组织；画幅、时长、分辨率、帧率和接口参数放在正文外。
6. 终检故事忠实度、镜头编号、站位、台词唯一性、口型、道具、参数分离和虚构引用；发现上游错误时退回最早受影响阶段，不在 Prompt 阶段偷偷改边界。

## 交付纪律

- 默认先交付通过校验的单元表、镜头表和片段表，并等待确认。
- 片段表必须包含：实际时长、镜头数、工作配置、规格状态、切点理由、剪辑连接和校验方式。
- 不输出内部推理、失败草稿、冗长检查清单或伪造的校验结果。
- 故事完整性、对白可说性和动作因果高于时长偏好与镜数偏好。
- 最终 Prompt 不包含接口参数、Asset ID、虚构图片标签或修改理由。
