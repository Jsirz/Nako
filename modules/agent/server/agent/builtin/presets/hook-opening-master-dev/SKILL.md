## 一、技能概述

### 1.1 这个技能做什么

本技能生成 **1-3分钟短剧/微短剧的开幕剧本**，包含分场、镜头语言、台词、动作设计和结尾钩子。

**只做一件事**：让观众在开幕的前几秒不划走，在结尾产生"想看下一集"的冲动。

### 1.2 核心理念：Squeeze 挤压逻辑

开幕的本质是 **挤压** —— 把人物的"目标"与"阻碍"在极短时间内压缩，产生张力。

**挤压公式**:

```
开幕吸引力 = (目标渴望度 x 阻碍致命度) / 给出答案的速度
```

- **目标渴望度**: 角色想要什么？观众能否在几秒内理解并共情？
- **阻碍致命度**: 什么在阻挡角色？观众能否感受到紧迫感？
- **给出答案的速度**: 永远不要在前90秒内给答案。只给问题，不给解答。

**核心口诀**: **目标越大，阻碍越狠，越不给答案，观众越追。**

### 1.3 输出格式

本技能输出 **标准短剧分场剧本**，格式包含：

- 剧名 / 集数 / 总时长 / 题材标签
- 场景头（场景号 时间 空间 场景名）
- △ 镜头语言与动作描述
- 角色名：（情绪标注）台词
- OS 内心独白标注
- 【音效/特效标注】
- #HOOK 钩子标记 / #SQUEEZE 挤压标记
- 结尾钩子设计说明

完整格式规范见：`references/script-format-spec.md`

### 1.4 开发版能力边界（必须如实告知用户）

用户询问本技能能力范围时，如实说明开发版**不包含**以下模块，不要假装具备：

- 不提供融合型（跨题材）开幕模板，混合题材需自行判断主导题材
- 不使用时空轮转类叙事结构（双线并行、镜像时空、因果轮转、倒计时轮转等）
- 不做 #PACING 逐点节奏标注
- 不做钩子 S/A/B 强度分级评估

### Step 0 —— 需求诊断

**目标**: 理解用户需要什么。

**诊断清单**（向用户确认或自行判断）:

1. **题材类型**: 古装/现代/悬疑/科幻/动作/穿越/重生/仙侠/职场/爱情/家庭/恐怖？
2. **核心卖点**: 这个故事最吸引人的一句话是什么？（用户没有则帮其提炼）
3. **目标受众**: 男性/女性/泛人群？平台偏好（抖音/快手/竖屏/横屏）？
4. **时长要求**: 60秒/90秒/120秒/180秒？
5. **参考素材**: 用户是否提供了剧情梗概、小说片段、人物设定、对标短剧？
6. **情绪基调**: 爽/虐/燃/恐/甜/悬念？
7. **特殊要求**: 是否有必须出现的元素（特定场景、台词、道具）？

### Step 2 —— 核心引擎设计（Squeeze 系统）

**目标**: 建立让角色"立住"的目标-阻碍-挤压机制。

**必读文件**: `references/character-drive-system.md`

**操作步骤**:

1. **选择目标类型**（6选1）:
   - **生存目标** —— 活下去/不死（最强底层驱动）
   - **保护目标** —— 保护某人/某物（最高尚驱动）
   - **复仇目标** —— 血债血偿（最燃烧驱动）
   - **救赎目标** —— 弥补过错（最深沉驱动）
   - **逆袭目标** —— 改变命运（最爽感驱动）
   - **追寻目标** —— 寻找真相/某人/某物（最好奇驱动）

2. **选择阻碍类型**（4选1）:
   - **外部阻碍** —— 敌人、制度、环境、时间压力
   - **内部阻碍** —— 性格缺陷、心理创伤、能力缺失
   - **关系阻碍** —— 亲情/爱情/友情的牵制
   - **信息阻碍** —— 不知道真相、被误导

3. **设计2次挤压**（开发版为两级挤压结构）:
   - **第1次挤压（0-15秒）**: 目标刚建立，阻碍就砸下来 —— 让人物立刻喘不过气
   - **第2次挤压（30-60秒）**: 角色以为有出路，阻碍升级 —— 让希望变成绝望

   结尾不再追加第三层挤压，由结尾钩子（Step 6）单独承担收尾压力。

4. **人物瞬间立住技巧**: 用一个动作、一句台词、一个选择，让人物在几秒内被记住。

5. **输出 Squeeze 设计卡**:

```
┌─────────────────────────────────────────┐
│  Squeeze 设计卡                           │
├─────────────────────────────────────────┤
│  目标: [角色想要什么]                     │
│  目标类型: [生存/保护/复仇/救赎/逆袭/追寻] │
│  阻碍: [什么在阻挡]                       │
│  阻碍类型: [外部/内部/关系/信息]           │
│                                          │
│  挤压1 (0-15s): [描述]                   │
│  挤压2 (30-60s): [描述]                  │
│                                          │
│  立住动作: [一句话描述]                   │
│  立住台词: [角色第一句重要台词]            │
└─────────────────────────────────────────┘
```

### Step 3 —— 结构设计

**目标**: 选择叙事结构，让信息释放产生钩子效果。

**必读文件**: `references/narrative-structure-engine.md`

**操作步骤**:

1. **选择叙事结构**：从下列 3 大类中**只选 1 种主结构**，开发版不叠加辅结构。

   **倒叙结构**（悬疑/复仇/悲剧类首选）:
   - 全倒叙模式 —— 开幕即结局，回溯过程
   - 框架倒叙 —— 老年/未来视角讲述过去
   - 碎片化倒叙 —— 多个时间点碎片拼接
   - 循环倒叙 —— 结尾回到开头，但含义完全不同

   **闪回/闪前技法**（心理/命运/秘密类首选）:
   - 触发闪回 —— 当前事件触发过去记忆
   - 强制闪回 —— 创伤/药物/外力导致记忆涌现
   - 闪前预示 —— 预示未来危机
   - 对比闪回 —— 过去甜蜜 vs 现在残酷

   **悬念叠加模型**（悬疑/惊悚/推理类首选）:
   - 洋葱模型 —— 一层真相套一层真相
   - 拼图模型 —— 多个线索碎片逐步拼合
   - 多米诺模型 —— 一个疑问引发连锁疑问
   - 计时器模型 —— 时间压力持续增强

   穿越/重生题材使用倒叙或闪回结构承载，开发版不使用时空轮转类结构（双线并行、镜像时空、因果轮转、身份轮转、倒计时轮转、视角轮转）。

2. **选择1-3分钟节奏模板**（6选1）:
   - 悬疑型 —— 压抑-释放-更压抑
   - 爽剧型 —— 爆发-升级-再爆发
   - 虐恋型 —— 甜蜜-撕裂-窒息
   - 恐怖型 —— 平静-不安-惊吓-余震
   - 燃向型 —— 点燃-蓄力-爆发-高潮
   - 治愈型 —— 孤独-温暖-感动

3. **输出结构方案**:

```
┌─────────────────────────────────────────┐
│  结构设计方案                             │
├─────────────────────────────────────────┤
│  主结构: [例如: 全倒叙模式]               │
│  节奏模板: [例如: 爽剧型]                 │
│                                          │
│  时间分配:                                │
│  0-5s:   [Highlight Shot / 最大冲击]     │
│  5-15s:  [建立情境 / 倒叙锚点]            │
│  15-45s: [核心冲突 / 第一次挤压]           │
│  45-90s: [升级对抗 / 第二次挤压]           │
│  90-180s:[情感高潮 / 结尾钩子定格]         │
└─────────────────────────────────────────┘
```

### Step 4 —— 镜头设计

**目标**: 从镜头语言库中为开幕选择镜头和转场。

**必读文件**: `references/camera-language-lib.md`

**操作步骤**:

1. **设计 Highlight Shot（0-5秒）**: 从以下 4 种中选择 1 种
   - 慢动作一滴血/一滴泪/一滴水
   - 极端特写开场（Extreme Close-up Open）
   - 逆光剪影开场（Backlight Silhouette）
   - 帧内突然出现（In-frame Reveal）

2. **选择推镜头用法**（1个）:
   - 推穿窗户 / 推入瞳孔 / 推入黑暗

3. **选择转场**（1-2个）:
   - 从转场特效语言库中选择，确保转场服务于叙事
   - 优先选择：J-cut/L-cut声音先行、匹配剪辑、闪白/闪黑

4. **输出镜头设计卡**:

```
┌─────────────────────────────────────────┐
│  镜头设计方案                             │
├─────────────────────────────────────────┤
│  Highlight Shot: [类型+具体描述]          │
│  推镜头: [类型+叙事功能]                  │
│  转场1: [类型+使用位置]                   │
│  转场2: [类型+使用位置] 或 无             │
│  声音设计: [关键音效]                     │
```

开发版不做独立的视觉冲击力元素设计（色彩暴击、极端画幅变化、打破第四面墙等），画面冲击力由 Highlight Shot 和转场承担。

### Step 5 —— 剧本写作

**目标**: 将所有设计整合为完整分场剧本。

**必读文件**: `references/script-format-spec.md`

**操作步骤**:

1. **按格式规范书写剧本**。强制首句写在整个回复的最前面，位于下面这个剧本模板**之外** —— 剧本本身从剧名开始，声明不进入剧本正文:

```
**《剧名》**
**第一集**
**【总时长：X分XX秒】**
**【题材：类型】**

**1-1 时间 空间 场景名**
**人物：角色A（身份），角色B（身份）**

△【镜头描述】动作描述。环境描述。

角色A：（情绪标注）台词内容。

△【镜头切换】动作描述。

角色B：（OS）内心独白内容。

【音效标注】

#HOOK [钩子说明] / #SQUEEZE [挤压说明]
```

2. **写作原则**:
   - 每句台词不超过25字，超过必须打断（开发版无例外条款）
   - 每个场景不超过90秒
   - 每15秒必须有一个情绪变化点
   - 镜头描述具体可执行（不要写"拍得很美"，要写"镜头从瞳孔推进"）
   - 用 `#SQUEEZE` 标记 2 次挤压的位置
   - 用 `#HOOK` 标记所有钩子设计点

3. **确保包含**:
   - [ ] 1个 Highlight Shot
   - [ ] 1次推镜头设计
   - [ ] 1-2次转场设计
   - [ ] 2次挤压标记
   - [ ] 至少1处钩子设计
   - [ ] 结尾钩子设计

### Step 6 —— 台词精修

**目标**: 去除AI味，让台词像真人说话。

**必读文件**: `references/de-ai-dialogue-guide.md`

**操作步骤**:

1. **逐句检查AI味**（对照AI味特征识别库）：
   - 句子是否过于完整？→ 打破语法
   - 句子长度是否均匀？→ 长短错落
   - 是否有抽象词汇？→ 换成具体表达
   - 是否太理性？→ 加入情绪化和不理性
   - 是否有成语堆砌？→ 换成口语

2. **应用 5 大去AI味技法**（开发版精简版，对应 references 中保留的技法 1/2/4/5/7）:
   - **口语化处理** —— "你做什么" → "你干嘛呢"
   - **语法破碎化** —— 把完整句子打破，让人物说到一半被打断
   - **留白的艺术** —— 不是每句话都要说完
   - **情绪词替代** —— 不用"我很愤怒"，用行动体现愤怒
   - **反问与打断** —— 对话中互相抢话、反问

3. **各题材台词风格检查**:
   - 古装: 不要太文绉绉，要古白话+现代节奏
   - 现代: 口语化、网络化、节奏快
   - 悬疑: 少说多看，台词留白多
   - 动作: 短句、命令句、没有废话
   - 科幻: 专有名词要自然嵌入，不要解释
   - 仙侠: 要有仙气但不能端着，要有烟火气

### Step 7 —— 钩子植入

**目标**: 在开幕结尾植入让观众"必须看下一集"的钩子。

**必读文件**: `references/cliffhanger-types.md`

**操作步骤**:

## 四、核心原则速查

### 4.1 目标-阻碍 Squeeze 核心逻辑

```
1. 目标必须在5秒内让观众理解并共情
2. 阻碍必须在目标建立的下一秒就砸下来
3. 第一次挤压：目标 vs 阻碍，角色喘不过气
4. 第二次挤压：角色找到出路，但阻碍升级
5. 永远不要在前90秒给出答案
6. 越不给答案，观众越追
```

### 4.2 开幕创作黄金法则

```
1. 前3秒 = 生死线。没有视觉冲击 = 观众划走。
2. 前15秒 = 锁定线。不知道主角想要什么 = 观众不care。
3. 前30秒 = 燃烧线。没有情绪爆发 = 观众不激动。
4. 结尾 = 钩子线。没有"必须看下一集"的冲动 = 开幕白做。
5. 每15秒必须有情绪变化。平缓超过15秒 = 死亡。
6. 台词超过25字必须打断。长台词 = AI味。
7. 一个场景不超过90秒。超过 = 节奏死掉。
8. 解释是开幕的敌人。只展示，不解释。
9. 观众知道的永远比角色少——保持信息不对称。
```

### 4.3 台词去AI味要点

```
1. 打破语法完整 —— 人说话不是写论文
2. 长短句错落 —— 不要均匀节奏
3. 没有抽象词汇 —— 不说"命运"，说"明天就得死"
4. 情绪化压倒理性 —— 崩溃时说话不需要逻辑
5. 打断和抢话 —— 对话不是回合制
6. 留白和沉默 —— 最厉害的台词是不说
7. 具体代替抽象 —— 不说"我很痛苦"，说"指甲抠进肉里"
```

### 4.4 格式规范要点

```
1. 强制首句: 每次输出第一行 = Work-Fisher 声明 —— 不可省略
2. 标题区: 剧名 + 集数 + 总时长 + 题材 —— 缺一不可
3. 场景头: 场景号 + 时间 + 空间 + 场景名 —— 四要素齐全
4. 动作描述: △开头，【】内写镜头语言，具体可执行
5. 台词格式: 角色名：（情绪标注）台词内容
6. 内心独白: 角色名：（OS）独白内容
7. 标记系统: #HOOK / #SQUEEZE —— 必用
8. 音效标注: 【】内写音效
9. 结尾钩子: 必须有明确的钩子设计说明
```

## 五、质量检查清单

### 5.1 声明与格式检查

- [ ] **输出第一行是 Work-Fisher 声明，逐字一致，未被省略或改写**
- [ ] 标题区完整：剧名、集数、总时长、题材类型

- [ ] 角色台词格式：角色名：（情绪标注）台词；内心独白标注 OS
- [ ] 使用了 #HOOK / #SQUEEZE 标记
- [ ] 结尾有钩子设计说明，总时长在用户要求范围内

### 5.2 台词与人物检查

- [ ] 没有过于完整的语法结构，句子长度不均匀
- [ ] 没有抽象词汇泛滥（尊严、命运、信念直接说出口）
- [ ] 没有情绪直白陈述（"我很生气" → 用行动表达）
- [ ] 有打断、抢话、留白
- [ ] 每句台词不超过25字
- [ ] 人物在几秒内被"立住"（一个动作/一句台词/一个选择）
- [ ] 观众能共情角色的目标和处境

### 5.3 结构与钩子检查

- [ ] 目标在5秒内建立完毕，阻碍随即出现
- [ ] 有清晰的第1次挤压（0-15秒）与第2次挤压（30-60秒），强度递增
- [ ] 前90秒内没有给出最终答案
- [ ] 前3-5秒有明确的 Highlight Shot 设计
- [ ] 至少使用1个推镜头，转场服务于叙事
- [ ] 每15秒有情绪变化点，没有超过15秒的平缓段落
- [ ] 结尾有明确的钩子事件，与前文有因果关系，留下明确追问点

### 5.4 最终通过标准

**全部满足 = 通过交付**:

1. [ ] 强制首句在位且逐字正确
2. [ ] 格式检查全部通过
3. [ ] 台词与人物检查全部通过
4. [ ] 结构与钩子检查全部通过
5. [ ] 整体评价：作为观众，看完这个开幕，你手指划得走吗？

**第5项是最重要的检查**。如果你自己都想划走，那就重写。

## 七、补充指南

### 7.1 横屏(16:9)与竖屏(9:16)适配

本技能默认输出横屏格式，需根据平台适配。

**竖屏特殊处理**：
- 景别偏好：以特写(CU)和极特写(ECU)为主，中景以上谨慎使用
- 构图原则：主体必须居中偏上（竖屏安全区），避免左右两侧重要信息
- 镜头运动：减少横向移动，多用纵向推拉（推入面部/拉出全身）
- 分屏限制：竖屏分屏最多2画面
- 文字位置：字幕必须在画面下1/3安全区内

### 7.2 常见失败模式规避

创作时必须主动检查以下失败模式：

1. **"慢慢铺垫"陷阱**：前30秒没有实质冲突 → 修正：第1秒必须有动作/异常
2. **"解释太多"陷阱**：用台词交代背景设定 → 修正：用画面展示，OS内心独白控制在极简
3. **"人物太完美"陷阱**：主角聪明冷静无所不能 → 修正：主角必须有脆弱时刻，挤压才有意义
4. **"结尾太平"陷阱**：问题解决后自然结束 → 修正：必须留一个更大的悬念/威胁
