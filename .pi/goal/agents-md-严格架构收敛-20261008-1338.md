# Goal

使当前项目的实际实现严格收敛到根目录 AGENTS.md 定义的模块边界、依赖流向和接口契约要求，并消除已确认的核心架构违规项。

# Acceptance criteria

- Agent 模块不再承担 Provider 协议解析、Provider 参数生成、API Key 解析或具体 HTTP 请求协议构造职责。
- Agent 模块不再直接依赖或感知具体 Provider 实现名称、Provider 密钥结构或 Provider 专属请求格式。
- 生成相关能力通过 generation 层统一服务或契约暴露，符合 AGENTS.md 中 generation-core 与 generation-providers 的职责划分。
- canvas-ui 不再直接调用 local-runtime 专用运行时接口，而是通过符合 AGENTS.md 的 kernel/contracts 服务边界访问相应能力。
- local-runtime 仅作为平台适配实现层，对外暴露契约化服务，不要求 canvas-ui 感知 local-runtime 具体实现。
- 模块依赖方向符合 AGENTS.md 要求，消除已确认的 Agent、Canvas、Workflow 相关跨层耦合。
- 所有受影响架构文档与源码实现保持一致，不存在失效引用、已删除文档引用或明显与真实实现冲突的说明。
- 保留现有有效业务能力，不通过简单删除业务功能的方式满足架构约束。
- 完成后能够基于源码检查，确认已解决本次已识别的核心违规点（Agent Provider 边界、Canvas 到 Runtime 边界、服务契约边界）。

# Boundaries

- 不修改与本次架构收敛无关的业务功能。
- 不引入新的跨模块违规依赖。
- 不以回滚、禁用或删除主要业务功能替代架构收敛。
- 不篡改架构文档以掩盖实际实现问题。
- 保留用户现有未提交修改，避免覆盖无关变更。
